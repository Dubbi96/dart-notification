> 상위 문서: [실행 로드맵](../../../roadmap/01-execution-roadmap.md) · [역할 매트릭스](../../../roadmap/roles/README.md)
> 📦 아카이브(2026-07-02): 구현 완료된 M0 기획 기록.

이 문서는 M0 단계에서 신규 사용자가 앱에 처음 진입하여 홈 피드를 보기까지의 온보딩 여정을 정의한다.
각 시나리오는 **트리거 → 분기 조건 → 성공 경로 → 실패/예외 처리 → 빈 상태**를 포함한다.

## SC-01 — 스플래시 & 진입 판단

**목적:** 앱 실행 시 인증 상태를 확인하고 적절한 화면으로 라우팅한다.

### 트리거

앱이 콜드스타트 또는 포그라운드 복귀 시 실행된다.

### 정상 경로

1. 스플래시 화면(로고 + Teal 배경) 표시 — 최대 2초.
2. `expo-secure-store`에서 `accessToken` 존재 여부 확인.
3. 토큰 존재 → JWT 만료 여부 확인.
   - 유효: 홈 피드(`/(tabs)/home`)로 이동.
   - 만료: Refresh Token으로 재발급 시도.
     - 재발급 성공: 홈 피드 이동.
     - 재발급 실패: 토큰 삭제 후 로그인 화면 이동.
4. 토큰 없음 → 로그인 화면 이동.

### 분기

| 조건 | 이동 대상 |
|------|-----------|
| 유효한 액세스토큰 존재 | 홈 피드 |
| 액세스토큰 만료 + Refresh 성공 | 홈 피드 |
| 액세스토큰 만료 + Refresh 실패 | 로그인 화면 |
| 토큰 없음 (최초 실행 포함) | 로그인 화면 |

### 실패/예외

- 네트워크 단절 상태에서 토큰 유효성 검사 불가 → 마지막 저장된 토큰 있으면 낙관적으로 홈 진입(오프라인 모드), 없으면 로그인 화면 이동.
- `expo-secure-store` 읽기 오류 → 로그인 화면 이동 + 스낵바 "앱을 다시 시작해 주세요".

## SC-02 — 카카오 로그인

**목적:** 카카오 OAuth를 통해 신원을 확인하고 JWT 토큰을 발급받는다.

### 트리거

로그인 화면에서 "카카오로 시작하기" 버튼 탭.

### 정상 경로

1. `expo-web-browser`로 카카오 OAuth 팝업 실행.
2. 카카오 계정 선택 / 자동 로그인.
3. 백엔드 `/auth/kakao/callback` 호출 → JWT Access Token + Refresh Token 발급.
4. 토큰을 `expo-secure-store`에 저장.
5. 신규 회원 판단(`isNewUser: true`) → 온보딩 SC-03으로 이동.
6. 기존 회원 → 홈 피드(SC-06)로 이동.

### 분기

| 조건 | 처리 |
|------|------|
| 신규 회원 (`isNewUser: true`) | 온보딩 스텝 시작 (SC-03) |
| 기존 회원 (`isNewUser: false`) | 홈 피드 바로 이동 |
| 온보딩 미완료 상태로 재진입 | 미완료 스텝부터 재개 |

### 실패/예외

- 카카오 팝업에서 사용자가 직접 닫음 → 로그인 화면 복귀, 토스트 없음(의도적 취소).
- 카카오 서버 오류(5xx) → 토스트 "잠시 후 다시 시도해 주세요".
- 백엔드 응답 지연(10초 초과) → 타임아웃 처리, "네트워크 연결을 확인해 주세요".
- 동일 이메일로 다른 provider 가입 이력 존재 → 백엔드 409 응답 → "이미 다른 방법으로 가입된 계정입니다".

## SC-03 — 분석 유니버스 & 관심종목 선택

**목적:** 사용자가 공시 알림을 받을 관심 기업을 선택한다. 이 단계에서 선택된 기업이 이후 알림 매칭 및 투자 이벤트 필터링의 기준이 된다.

### 트리거

신규 회원 최초 로그인 직후, 또는 온보딩 미완료 상태 재진입 시.

### 정상 경로

1. 화면 상단에 인기 기업 추천 목록 표시 (Watch List 집계 기반, 콜드 스타트 시 대기업 큐레이션 fallback).
2. 기업 검색창으로 DART corpName 자동완성 검색 가능 (`GET /companies/search`).
3. 기업 칩(chip)을 탭하면 선택/해제. 선택된 기업은 강조 표시.
4. "다음" 버튼 탭 → 선택된 기업 목록을 백엔드 Watch List에 일괄 등록 (`POST /watch-lists`).
5. SC-04로 이동.

### 분기

| 조건 | 처리 |
|------|------|
| 1개 이상 선택 후 "다음" | Watch List 등록 후 SC-04 |
| 0개 선택 후 "다음" (건너뜀) | 유도 바텀시트 표시 후 SC-04 |
| 검색 결과 없음 | "검색 결과가 없습니다" 안내 |

### 관심종목 미선택 유도 시나리오

사용자가 아무 기업도 선택하지 않고 "건너뜀" 또는 "다음"을 탭하면 다음 유도 흐름이 실행된다.

1. 바텀시트 표시:
   - 제목: "관심 기업을 등록하면 알림이 바로 시작돼요"
   - 본문: "공시가 발생하면 선택한 기업의 알림만 받을 수 있어요. 나중에 설정에서 언제든 추가할 수 있어요."
   - 버튼 두 개: "기업 선택하기 (강조)" / "나중에 하기"
2. "기업 선택하기" → 바텀시트 닫고 현재 화면 유지 (재선택 기회 제공).
3. "나중에 하기" → SC-04로 이동.
4. SC-04~SC-05 완료 후 홈 진입 시 홈 화면에 고정 배너 표시:
   - "관심 기업을 아직 등록하지 않았어요. [등록하러 가기]"
   - 배너는 최초 Watch List 등록 시 자동으로 사라진다.

### 빈 상태

- 인기 기업 API 응답이 비어 있거나 오류 → "아직 인기 기업 데이터가 없어요. 검색으로 직접 찾아보세요." 표시 + 검색창 자동 포커스.
- 네트워크 오류로 추천 목록 로드 실패 → 검색만 가능한 fallback UI.

### 알림 카피 톤 (이 화면)

- "관심 기업의 중요 공시가 생기면 알려드려요."
- "(참고용 정보입니다. 투자 결정은 본인이 하세요.)" — 화면 하단 소문자 캡션.

## SC-04 — Persona 선택

**목적:** 사용자의 투자 성향(Persona)을 선택하여 이후 AI 분석 결과의 해석 방향을 개인화한다. M3 이후 `PersonaAnalysis`의 입력값으로 사용된다.

> M0 단계에서는 Persona 데이터를 저장만 하고, AI 분석(PersonaAnalysis)은 M3에서 구현된다.

### 4종 Persona 정의

| Persona 코드 | 표시 이름 | 한 줄 설명 |
|-------------|----------|-----------|
| `VALUE` | 가치 투자자 | 저평가 주식을 찾아 장기 보유하는 스타일 |
| `GROWTH` | 성장 투자자 | 고성장 기업에 집중, 미래 가치 중시 |
| `MOMENTUM` | 모멘텀 투자자 | 시세 흐름과 수급을 따라 단중기 매매 |
| `EVENT_DRIVEN` | 이벤트 투자자 | 공시·이슈를 빠르게 포착해 단기 대응 |

### 트리거

SC-03 완료(또는 건너뜀) 후 자동 이동.

### 정상 경로

1. 4종 Persona 카드 표시 (아이콘 + 이름 + 한 줄 설명).
2. 사용자가 1개 선택 → 해당 카드 강조.
3. "다음" 탭 → `PATCH /users/me`에 `personaCode` 저장.
4. SC-05로 이동.

### 분기

| 조건 | 처리 |
|------|------|
| Persona 1개 선택 후 "다음" | 저장 후 SC-05 |
| 선택 없이 "건너뜀" 또는 "다음" | 기본값 자동 지정 후 SC-05 |

### Persona 미선택 기본값 처리

사용자가 Persona를 선택하지 않고 다음 단계로 넘어가면:

1. 유도 멘트 없이 조용히 기본값 `EVENT_DRIVEN`(이벤트 투자자)을 자동 지정한다.
   - 이유: DART 공시 앱 특성상 이벤트 기반 알림이 서비스 핵심이므로 가장 자연스러운 기본값.
2. 홈 진입 후 설정 탭에서 언제든 변경 가능함을 안내 (홈 최초 진입 시 1회만 토스트: "투자 성향은 설정에서 언제든 바꿀 수 있어요.").
3. Persona 미선택 상태는 `personaCode: 'EVENT_DRIVEN'` + `isPersonaManuallySet: false` 플래그로 구분 저장한다 (설정 화면에서 "아직 성향을 선택하지 않으셨어요" 표시 용도).

### 빈 상태 / 예외

- Persona 목록 로드 실패(네트워크 오류) → 로컬 하드코딩 4종 카드 표시 (API 의존 없이 항상 보임).
- `PATCH /users/me` 저장 실패 → 로컬에 임시 저장 후 다음 API 성공 시 동기화, 현재 화면은 SC-05로 진행.

## SC-05 — 고지 동의

**목적:** 투자 비자문 고지 및 서비스 이용 약관에 동의를 받는다. M0 단계의 컴플라이언스 필수 게이트.

### 트리거

SC-04 완료 후 자동 이동.

### 정상 경로

1. 고지 화면 표시. 아래 항목을 모두 포함:
   - **필수 ①** 서비스 이용약관 동의
   - **필수 ②** 개인정보 처리방침 동의
   - **필수 ③** 투자 비자문 고지 확인

2. "전체 동의" 체크박스 탭 → 3개 항목 일괄 선택.

3. 또는 항목별 개별 체크.

4. 3개 필수 항목 모두 체크된 상태에서 "시작하기" 탭 → 동의 내역 서버 저장 → SC-06(홈 피드) 이동.

### 투자 비자문 고지 문구 (필수 ③)

```
이 앱은 DART(금융감독원 전자공시시스템)의 공시 정보를 수집·분류·요약하여
알림으로 전달하는 정보 서비스입니다.

제공되는 모든 정보는 참고용이며, 투자를 권유하거나
매수·매도·보유를 조언하지 않습니다.

투자 결정과 그에 따른 결과는 전적으로 이용자 본인의 책임입니다.
```

### 분기

| 조건 | 처리 |
|------|------|
| 3개 필수 항목 모두 동의 + "시작하기" | 홈 피드(SC-06) 이동 |
| 1개 이상 미체크 상태에서 "시작하기" 탭 | 미체크 항목 강조(빨간 테두리) + "필수 항목에 모두 동의해 주세요" 토스트 |
| "뒤로가기" 탭 | SC-04로 복귀 (Persona 선택 다시 가능) |

### 실패/예외

- 동의 내역 서버 저장 실패(네트워크 오류) → 로컬에 임시 저장 후 백그라운드 재시도(최대 3회), 홈 피드는 정상 진입.
- 재시도 전부 실패 → 다음 앱 실행 시 동의 화면부터 다시 시작 (고지 누락 방지).

### 알림 카피 톤 (이 화면 + 서비스 전반)

이 서비스의 알림·분석 관련 모든 카피는 아래 톤 가이드를 따른다.

| 원칙 | 예시 |
|------|------|
| 사실 중심 서술 | "삼성전자가 자사주 취득 결정을 공시했어요." |
| 투자 자문 표현 금지 | "매수하세요", "좋은 기회예요" 표현 사용 금지 |
| 참고용 맥락 명시 | "이 알림은 공시 정보를 전달하는 참고용입니다." |
| 수치는 공시 원문 인용 | "취득 예정 금액: 500억 원 (공시 원문 기준)" |
| 불확실성 표현 포함 | "AI 분석은 참고용이며 실제 결과와 다를 수 있어요." |
| 알림 제목 포맷 | `{기업명} {이벤트 유형} 공시` |
| 알림 본문 포맷 | `{보고서명} — 참고용 정보입니다.` |

## SC-06 — 홈 피드 최초 진입

**목적:** 온보딩 완료 후 홈 피드를 처음 보여준다. 온보딩 결과(관심종목 유무, Persona 설정 여부)에 따라 화면 상태가 달라진다.

### 트리거

SC-05 고지 동의 완료, 또는 기존 회원 로그인 성공.

### 케이스별 홈 상태

#### 케이스 A — 관심종목 O + Persona O (정상 완료)

1. "관심" 탭 활성 상태로 피드 표시.
2. 등록된 기업의 최근 공시 목록 표시.
3. 공시가 아직 없으면 빈 상태(SC-06-E1 참고).

#### 케이스 B — 관심종목 없음 + Persona O

1. 홈 피드 상단에 고정 배너:
   - "아직 관심 기업이 없어요. 지금 등록하면 맞춤 알림을 받을 수 있어요. [등록하기]"
2. "전체" 탭으로 전체 공시 피드 표시.
3. [등록하기] 탭 → 관심기업 검색 모달 진입.
4. 배너는 Watch List 1건 이상 등록 시 자동 숨김.

#### 케이스 C — 관심종목 O + Persona 미선택 (기본값 자동 지정)

1. 정상 홈 피드 진입 (케이스 A와 동일 UI).
2. 홈 최초 진입 시 토스트 1회: "투자 성향은 설정에서 언제든 바꿀 수 있어요."
3. 설정 탭의 프로필 섹션에 "성향 설정하기" 배지 표시 (미선택 상태 안내).

#### 케이스 D — 관심종목 없음 + Persona 미선택

케이스 B + 케이스 C를 동시에 적용한다.

### 빈 상태 (SC-06-E1)

관심 탭에서 공시가 하나도 없을 때:

- 일러스트 + 메시지: "아직 공시가 없어요."
- 서브텍스트: "관심 기업의 새 공시가 생기면 바로 알려드려요."
- 버튼: "관심 기업 추가하기" (관심기업 검색 모달로 이동)

## 시나리오별 알림 카피 원문 참고

아래 카피는 SC-02~SC-06 및 이후 서비스 전반에서 사용하는 알림/푸시 문구의 톤 앤 매너를 보여주는 예시다.

### 공시 발생 푸시 알림

```
제목: 삼성전자 자기주식 취득 공시
본문: [주요사항보고] 자기주식 취득 결정 · 공시 원문에서 확인하세요.
(이 알림은 투자를 권유하지 않는 참고용 공시 정보입니다.)
```

### 관심종목 미등록 유도 인앱 배너

```
관심 기업을 등록하면 공시 알림이 시작돼요.
[기업 찾아보기] 버튼으로 원하는 기업을 검색해 보세요.
```

### Persona 기본값 안내 토스트

```
투자 성향(이벤트 투자자)이 기본으로 설정됐어요.
설정 > 투자 성향에서 언제든 바꿀 수 있어요.
```

### 고지 화면 하단 캡션 (소문자, 회색)

```
이 앱은 공시 정보를 전달하는 참고용 서비스입니다.
투자 손익에 대한 책임은 이용자 본인에게 있습니다.
```

## M0 구현 의존성 노트

이 시나리오가 동작하려면 아래 M0 백엔드 산출물이 완료되어야 한다.

| 시나리오 | 의존 API / 기능 |
|----------|---------------|
| SC-01 | `expo-secure-store` 토큰 저장, `/auth/refresh` |
| SC-02 | `/auth/kakao/callback`, JWT 발급, `isNewUser` 응답 필드 |
