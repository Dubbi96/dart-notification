## 2. 🟡 만들다 만 / 불완전한 기능

| 항목 | 현재 상태 | 남은 일 |
|------|-----------|---------|
| **로컬 이메일 가입/로그인 UX** | 백엔드 API는 살아있으나 모바일 `sign-up` 화면 제거됨 | 카카오 단독으로 갈지 결정 → 갈 거면 백엔드 local-auth 정리, 아니면 화면 복구 |
| **Google OAuth** | 미구현(흔적 없음) | 계획상 3순위였음. 추가 로그인 필요 시 구현 |
| **시장 구분(KOSPI/KOSDAQ)** | 시드가 상장 여부만 판별(`LISTED`), 실제 시장 구분 안 됨 | 별도 종목 데이터 소스 필요 |
| **테스트 코드** | 단위/E2E 테스트 전무 | 최소 핵심 서비스(스케줄러 매칭, 인증) 테스트 |
| **마이그레이션 git 추적** | 정상 추적됨(5개 모두 커밋) | 루트 `.gitignore`의 `prisma/migrations/**` 규칙은 `backend/` 접두사 때문에 미적용 → 결과적으로 추적됨. 의도된 동작인지만 확인 |
| **HTTPS** | ALB가 **HTTP**로 노출 | 도메인 + ACM 인증서 + HTTPS 리스너 |
| **CI/CD** | 자동 빌드/배포 파이프라인 없음(수동) | GitHub Actions 등 |
| **테스트용 시드** | `seed-notifications.ts`는 개발 편의용(운영 무관) | 정리/문서화만 |

## 3. 🎯 지금 이 프로젝트로 "가능한 것" (기능 정의 확정)

> 결론: **DART 공시 실시간 알림 MVP가 端-to-端으로 동작 가능한 상태.** 데모/내부 테스트 배포까지 가능.

사용자가 지금 할 수 있는 일:
1. 카카오로 로그인한다.
2. 관심 기업을 검색해 등록한다(온보딩에서 인기 기업 추천).
3. 받고 싶은 공시 유형(7종)과 키워드, 알림 on/off를 설정한다.
4. 백엔드가 평일 자동(10분 주기)으로 DART 공시를 수집한다.
5. 내 조건(관심기업 + 유형 + 키워드)에 맞는 공시가 뜨면 **푸시 알림**을 받는다.
6. 알림을 누르면 해당 **공시 상세/원문(WebView)** 으로 딥링크 이동한다.
7. 공시를 **저장(북마크)** 하고 나중에 다시 본다.
8. 기업 상세(기업개황)를 확인한다.
9. 알림 히스토리를 읽음 처리/관리한다.

운영자가 할 수 있는 일:
- `POST /scheduler/collect`로 과거 날짜 공시를 수동 백필.
- AWS(ECS/RDS)에서 백엔드 가동, EAS로 안드로이드 내부 배포(APK/AAB).

**아직 불가능한 것:** Google 로그인, 정확한 시장 구분, 자동화된 테스트/CI, HTTPS 정식 도메인, (1차 제외 범위인) AI 요약·중요도 판단·이메일/카톡 알림·웹 지원.

## 4. ⚠️ 인수자가 바로 짚어야 할 리스크 (우선순위)

1. **HTTP 평문 배포** — ALB가 HTTP. 토큰이 평문 전송됨. 정식 사용 전 HTTPS(도메인+ACM) 필수.
2. **테스트 0** — 스케줄러 매칭·인증 회귀 위험. 핵심 경로부터 테스트 추가.
3. **시크릿 관리** — DART/Kakao/JWT 키 운영 주입 경로(ECS task env/Secrets Manager) 점검.
4. **Terraform 산출물** — `infra/tfplan`은 시크릿 포함 가능성이 있어 git에서 제외함(`infra/.gitignore`에 추가). `tfstate`는 S3 백엔드 사용 중.
