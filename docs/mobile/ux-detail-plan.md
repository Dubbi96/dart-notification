## 1. 검색 UX (최우선)

> 사용자가 명시한 최우선 개선 항목. "관심기업/종목 검색 같은 것들"

### 1-1. 검색 진입점 배치

**현재 상태**: 관심기업 추가가 설정→관심목록에서만 가능. 검색 진입이 깊음.

**개선안**:

| 화면 | 진입점 | 진입 방식 |
|---|---|---|
| 홈 피드 상단 | 검색 아이콘 (feather:`search`) | 탭 → 검색 오버레이 |
| 공시 목록 상단 | `Searchbar` 고정 | 탭 → 키보드 포커스 |
| 관심목록 | FAB `+` 또는 헤더 아이콘 | 탭 → 검색 오버레이 |
| 신호 피드 필터 | Persona/종목 필터 Chip | 탭 → 필터 Bottom Sheet |

---

### 1-2. 검색 오버레이 UX (관심기업·종목 추가)

**레이아웃**:
```
┌──────────────────────────────────────────┐
│  ← [검색어 입력...]              [취소]  │  ← Searchbar (항상 포커스)
│  ─────────────────────────────────────  │
│  최근 검색                              │  ← RecentSearchSection
│  삼성전자   SK하이닉스   POSCO           │
│  (각 항목 우측 × 삭제 버튼)             │
│                                          │
│  인기 종목                              │  ← PopularSection (검색어 없을 때)
│  ┌───────────────────────────────────┐  │
│  │ 1. 삼성전자    005930  [★추가]    │  │  ← PopularItem
│  │ 2. SK하이닉스  000660  [★추가]   │  │
│  │ 3. POSCO홀딩스 005490  [★추가]   │  │
│  └───────────────────────────────────┘  │
└──────────────────────────────────────────┘
```

**검색 중 레이아웃**:
```
┌──────────────────────────────────────────┐
│  ← [삼성▌]                    [취소]    │
│  ─────────────────────────────────────  │
│  검색 결과 (3개)                        │  ← 결과 수 표시
│  ┌───────────────────────────────────┐  │
│  │ 삼성전자     005930  KOSPI  [+]   │  │  ← 종목명 · 코드 · 시장
│  │ 삼성SDI     006400  KOSPI  [+]   │  │  ← 이미 추가된 경우 [✓] 표시
│  │ 삼성바이오로직 207940 KOSPI [+]  │  │
│  └───────────────────────────────────┘  │
└──────────────────────────────────────────┘
```

**자동완성 규칙**:
- 입력 시작 즉시 로컬 캐시 결과 표시 (staleTime 5분)
- 2글자 이상 시 API 호출 (debounce 300ms)
- 한글 조합 중(composing)에는 API 호출 하지 않음 (`onChangeText` vs `onSubmitEditing` 구분)
- 종목코드 6자리 입력 시 자동완성 없이 직접 검색

**결과 아이템 구성**:
```
[종목명]   [종목코드]   [시장구분]   [추가/제거 버튼]
삼성전자   005930      KOSPI        [+ 추가]
           ← bold    ← caption    ← 이미 추가됨: [✓] (primary색, 탭하면 제거)
```

**추가/제거 인터랙션**:
- `[+ 추가]` 탭 → 낙관적 업데이트(즉시 `[✓]`로 전환) + 서버 반영 + Snackbar "삼성전자를 관심목록에 추가했습니다. [실행 취소]"
- `[✓]` 탭 → 낙관적 업데이트(즉시 `[+]`로 전환) + 서버 반영 + Snackbar "삼성전자를 관심목록에서 제거했습니다."
- 서버 오류 시 낙관적 업데이트 롤백 + Snackbar "추가에 실패했습니다. 다시 시도해 주세요."

**키보드 처리**:
- 오버레이 진입 즉시 키보드 표시 (`autoFocus={true}`)
- `returnKeyType="search"`, `onSubmitEditing` → 검색 실행
- 백버튼/Swipe down → 키보드 닫기 → 오버레이 닫기 (역순)
- `[취소]` → 키보드 + 오버레이 동시 닫기

**빈 검색 결과**:
```
🔍 검색 결과가 없습니다.
"삼성전기"을 다시 확인하거나
종목코드 6자리로 검색해 보세요.
```
(검색어 텍스트를 따옴표 안에 표시)

**상태 정의**:

| 상태 | 화면 |
|---|---|
| 검색어 없음 | 최근검색 + 인기종목 |
| 2글자 미만 입력 | 최근검색 + 인기종목 (API 호출 안 함) |
| 로딩 중 | `ActivityIndicator` 검색 결과 자리에 |
| 결과 있음 | 결과 리스트 |
| 결과 없음 | 빈 상태 + 가이드 텍스트 |
| 네트워크 오류 | "검색에 실패했습니다. 인터넷 연결을 확인해 주세요." |

**접근성**:
- `Searchbar` `accessibilityLabel="관심 기업 검색"`, `accessibilityHint="종목명 또는 종목코드 6자리로 검색하세요"`
- 결과 아이템 `accessibilityLabel="삼성전자 종목코드 005930 코스피, 추가 버튼"` (종목 추가 전) / `"삼성전자, 관심목록에 추가됨. 탭하면 제거"` (추가 후)
- `[취소]` `accessibilityRole="button"`, `accessibilityLabel="검색 취소"`

### 1-3. 공시 검색 UX

**진입**: 공시 목록 상단 `Searchbar` (고정)

**검색 범위**: 공시 제목(`reportName`) + 기업명(`corpName`)

**레이아웃**:
```
┌──────────────────────────────────────────┐
│  🔍 [공시명 또는 기업명 검색...        ] │  ← Searchbar (고정 상단)
│  ─────────────────────────────────────  │
│  [전체] [공급계약] [자사주] [배당] ...   │  ← 이벤트 타입 필터 (스크롤 가능 Chip Row)
│                                          │
│  검색 결과 23건 · "삼성전자"            │  ← 결과 수 + 검색어 표시
│  ┌───────────────────────────────────┐  │
│  │ [공급계약] 삼성전자               │  │
│  │ 대규모 공급계약 체결의 건          │  │  ← 검색어 볼드 처리
│  │ 2026.06.05                        │  │
│  └───────────────────────────────────┘  │
└──────────────────────────────────────────┘
```

**검색어 하이라이트**: 결과에서 검색어 일치 부분 `bold` + `primary` 색상 처리

**필터 + 검색 조합**: 이벤트 타입 필터와 텍스트 검색 동시 적용. 필터 Chip 활성화 시 카운트 배지 표시.

## 2. 빈·로딩·에러 상태 상세

> 현재 빈 상태가 밋밋함 → 각 화면별 구체적 마이크로카피 + 액션

### 2-1. 상태 처리 기준

**스켈레톤 vs 스피너 기준**:
- **스켈레톤**: 레이아웃 구조가 예측 가능한 리스트·카드 (공시 피드, 신호 피드, 포트폴리오)
- **스피너**: 전체 화면 로딩, 형태 불확실한 단일 데이터 (공시 상세, Thesis 상세 초기 로드)
- **인라인 스피너**: 추가 로드(무한 스크롤 페이지네이션, 검색 중) — 리스트 하단 소형 `ActivityIndicator`

**에러 재시도**:
- 네트워크 오류: "인터넷 연결을 확인해 주세요." + [재시도]
- 서버 오류(5xx): "일시적 오류가 발생했습니다. 잠시 후 다시 시도해 주세요." + [재시도]
- 데이터 없음(404): 화면별 빈 상태 메시지 (재시도 버튼 없음)
- [재시도] → `refetch()` 호출 + 스켈레톤 다시 표시

---

### 2-2. 화면별 마이크로카피 테이블

| 화면 | 빈 상태 메시지 | 보조 액션 | 아이콘 |
|---|---|---|---|
| 홈 피드 (관심기업 없음) | 관심 기업을 추가하면 맞춤 공시를 보여드려요 | [관심 기업 추가] | feather:`star` |
| 홈 피드 (공시 없음) | 오늘 공시가 아직 없어요. 장 시간 중 업데이트됩니다 | — | feather:`clock` |
| 공시 목록 (필터 결과 없음) | 선택한 필터에 맞는 공시가 없어요 | [필터 초기화] | feather:`filter` |
| 알림 피드 (로그인 전) | 로그인하고 알림을 받아보세요 | [로그인] | feather:`bell` |
| 알림 피드 (알림 없음) | 알림이 아직 없어요. 공시가 발생하면 바로 알려드릴게요 | — | feather:`bell-off` |
| 신호 피드 (관심기업 없음) | 관심 기업을 추가하면 매수 신호를 알려드려요 | [관심 기업 추가] | feather:`trending-up` |
| 신호 피드 (신호 없음) | 현재 조건에 맞는 신호가 없어요. 새 공시 발생 시 알려드릴게요 | — | feather:`zap-off` |
| 신호 피드 (필터 결과 없음) | 선택한 조건에 맞는 신호가 없어요 | [필터 초기화] | feather:`sliders` |
| 포트폴리오 (포지션 없음) | 보유 종목이 없어요. 매수 후보 탭에서 신호를 확인해 보세요 | [신호 탭으로] | feather:`briefcase` |
| 매도 신호 (없음) | 매도 신호가 없어요. 모든 포지션이 안전 구간에 있어요 | — | feather:`shield` |
| 저장된 공시 (없음) | 저장된 공시가 없어요. 공시 상세에서 북마크 버튼을 탭해 보세요 | — | feather:`bookmark` |
| 관심목록 (없음) | 아직 관심 기업이 없어요. 검색해서 추가해 보세요 | [기업 검색] | feather:`star` |
| 주문 승인 대기 (없음) | 대기 중인 주문안이 없어요 | — | feather:`check-circle` |
| 주문 이력 (없음) | 아직 처리된 주문이 없어요 | — | feather:`clock` |
| AI 비용 (데이터 없음) | AI 분석이 아직 실행되지 않았어요 | — | feather:`cpu` |
| 모의투자 (시작 전) | 모의투자를 시작하면 AI 신호 기반 가상 주문이 진행돼요 | [시작하기] | feather:`play-circle` |

```
│                            │
│  [메인 메시지]              │  ← Text(body, textSecondary), 가운데 정렬
│  [보조 설명 (있으면)]       │  ← Text(caption, textTertiary)

```

## 3. 피드백·마이크로인터랙션

### 3-1. Snackbar / Toast 규칙

**Snackbar (하단 고정, RN Paper)**:
- **사용 케이스**: 성공/실패 피드백 (관심기업 추가/제거, 저장/삭제, 복사, 알림 설정 변경)
- **표시 시간**: 성공 2.5초, 실패 4초 (실패는 더 길게)
- **액션 버튼**: 최대 1개 ("실행 취소", "재시도", "설정으로") — 중요도 높은 경우만
- **동시 표시**: 큐잉(FIFO). 앞의 Snackbar가 사라지기 전 새 Snackbar → 즉시 교체
- **위치**: 하단 탭바 위 (BottomSheet가 열린 경우 BottomSheet 위)

**Toast (모달형, 즉각 확인 필요)**:
- **사용 케이스**: 오류 확인 필요 시 (주문 승인 오류, 네트워크 오류)
- 일반적으로는 Snackbar 우선. Toast는 사용자가 명시적으로 닫아야 하는 경우만.

**마이크로카피 예시**:

| 액션 | 성공 Snackbar | 실패 Snackbar |
|---|---|---|
| 관심기업 추가 | "{종목명}을 관심목록에 추가했어요. [실행 취소]" | "추가에 실패했어요. 다시 시도해 주세요." |
| 관심기업 제거 | "{종목명}을 관심목록에서 제거했어요. [실행 취소]" | — |
| 공시 저장 | "공시를 저장했어요. [저장된 공시 보기]" | "저장에 실패했어요." |
| 공시 저장 취소 | "저장된 공시에서 제거했어요." | — |
| 알림 읽음 | — (자동) | — |
| 전체 읽음 | "{N}개의 알림을 모두 읽었어요." | — |
| 링크 복사 | "링크를 복사했어요." | — |
| 주문 승인 전송 | "주문을 전송 중입니다..." (진행 중) → "주문이 전송됐어요." | "주문 전송에 실패했어요. [재시도]" |

---

### 3-2. 낙관적 업데이트 UX

**적용 대상**: 관심기업 추가/제거, 공시 북마크, 알림 읽음 처리

**패턴**:
1. 탭 즉시 → 로컬 UI 상태 변경 (버튼 상태 전환)
2. Snackbar 표시 (성공 가정)
3. 서버 요청 전송 (`useMutation`)
4. 성공: 캐시 무효화 (`invalidateQueries`)
5. 실패: 로컬 UI 상태 롤백 + 실패 Snackbar 표시

**`[실행 취소]` 버튼**:
- Snackbar의 `[실행 취소]` 탭 → 즉시 반대 API 호출 (낙관적 업데이트 롤백 불필요, 새 요청)
- 2.5초 이내에만 표시 (Snackbar 사라지면 실행 취소 불가)

---

### 3-3. Pull-to-Refresh

**적용 화면**: 홈 피드, 공시 목록, 알림 피드, 신호 피드, 포트폴리오

**구현 기준**:
```tsx
<FlatList
  refreshControl={
    <RefreshControl
      refreshing={isRefetching}
      onRefresh={refetch}
      tintColor={colors.primary}
      colors={[colors.primary]}  // Android
    />
  }
/>
```

**UX 규칙**:
- 새로고침 완료 후 새 항목이 있으면 상단에 조용히 추가 (스크롤 위치 유지)
- 새 항목이 많으면 "새 공시 {N}개" 플로팅 배너 상단 표시 → 탭 시 최상단으로 이동
- 이미 최상단에서 pull-to-refresh → 즉시 새로고침 (스크롤 반응 없이)

---

### 3-4. 로딩 인디케이터 위치 기준

| 상황 | 인디케이터 | 위치 |
|---|---|---|
| 최초 화면 로드 | 스켈레톤 | 카드 자리 |
| 무한 스크롤 추가 로드 | `ActivityIndicator` (소형, 24dp) | 리스트 하단 |
| 버튼 탭 후 서버 응답 대기 | 버튼 내 `ActivityIndicator` | 버튼 텍스트 대체 |
| 페이지 전환 (Push navigation) | 없음 (즉각 전환) | — |
| 모달 내 서버 응답 대기 | 모달 내 `ActivityIndicator` | 모달 중앙 |
| Pull-to-refresh | `RefreshControl` | 리스트 최상단 |
| 배경 API (알림 폴링) | 없음 (사용자 비가시) | — |

### 3-5. 햅틱 피드백 (가능 시)

| 액션 | 햅틱 종류 |
|---|---|
| 주문 승인 [실행] | `impactAsync(Heavy)` — 중요한 의사결정 |

| 관심기업 추가 | `impactAsync(Light)` |

## 4. 네비게이션·플로우 상세

### 4-1. 탭 전환 동작

**탭 탭 시 동작 규칙**:
- 현재 탭 재탭 + 최상단에 있음 → `refetch()` 실행 (새로고침)
- 현재 탭 재탭 + 스크롤 내려가 있음 → 최상단으로 스크롤 이동 (`scrollToOffset(0)`)
- 다른 탭 탭 → 스크롤 위치 유지 (각 탭의 `FlatList ref` 별도 관리)

**탭 배지 업데이트 타이밍**:
- 알림 탭 배지: 실시간 (WebSocket 또는 폴링 30초)
- 신호 탭 배지 (주문 대기): `OrderRequest` 생성 시 푸시 알림과 동시에
- 포트폴리오 탭 배지 (VIOLATED 수): 포트폴리오 포커스 시 재계산

---

### 4-2. 뒤로가기 처리

**기본 규칙**:
- 모달/Bottom Sheet: 백버튼 → 닫기
- 검색 오버레이: 백버튼 → 키보드 닫기 → 두 번 탭 시 오버레이 닫기
- 상세 화면(공시/신호/포지션): 백버튼 → 이전 화면 (스택 pop)
- 탭 화면에서 백버튼: Android → 앱 종료 대신 홈 탭으로 이동 (또는 시스템 기본)
- 공시 원문 WebView에서 백버튼: WebView 내 뒤로가기 → 이전 페이지 없으면 화면 닫기

---

### 4-3. 딥링크 (gongsion://) 처리

**딥링크 스킴**: `gongsion://`

| 딥링크 URL | 이동 화면 | 처리 규칙 |
|---|---|---|
| `gongsion://disclosure/{rcpNo}` | 공시 상세 | 비로그인 허용 |
| `gongsion://signal/{signalId}` | 신호 상세 | 로그인 필요 → 로그인 화면 후 돌아옴 |
| `gongsion://orders/pending` | 주문 승인 대기 | 로그인 필요 |
| `gongsion://portfolio` | 포트폴리오 | 로그인 필요 |
| `gongsion://company/{corpCode}` | 기업 상세 | 비로그인 허용 |

**푸시 알림 → 딥링크 연결**:

| 알림 종류 | 탭 시 이동 |
|---|---|
| 공시 알림 | 공시 상세 (`/disclosure/{rcpNo}`) |
| 매수 신호 | 신호 상세 (`/signals/{signalId}`) |
| EXIT 신호 | 포트폴리오 매도 신호 탭 (`/(tabs)/portfolio?tab=exit&highlight={signalId}`) |
| 주문안 도착 (M11) | 주문 승인 대기 (`/orders/pending`) |
| 모의[주문] 체결 (M10) | 모의 포트폴리오 (`/(tabs)/portfolio?tab=paper`) |

**로그인 필요 딥링크 처리**:
1. 딥링크 URL 저장 (전역 상태 또는 `expo-secure-store`)
2. 로그인 화면으로 이동
3. 로그인 성공 → 저장된 딥링크 URL로 이동

---

### 4-4. 화면 간 데이터 전달

**기준**:
- **Route params 사용**: ID 값 (rcpNo, signalId, corpCode, positionId 등) — 간단한 스칼라 값
- **React Query 캐시 사용**: 리스트에서 상세로 이동 시 이미 캐시된 데이터 즉시 표시 (skeleton 없이), 백그라운드에서 fresh data fetch
- **금지**: Zustand에 서버 데이터 복제, 복잡한 객체를 route params로 전달

**캐시 활용 패턴 (리스트→상세)**:
```
공시 목록 → 공시 상세
  1. 리스트에서 rcpNo만 params로 전달
  2. 상세 화면: useQuery(['disclosures', rcpNo])
  3. queryClient에 이미 캐시된 경우 → 즉시 표시 (placeholderData 또는 initialData)
  4. 백그라운드 최신 데이터 fetch (staleTime 이후)
```

---

### 4-5. 모달 vs 푸시 기준

| 케이스 | 선택 | 이유 |
|---|---|---|
| 검색 오버레이 | 모달(전체 화면) | 키보드와 함께 전체 집중 |
| 필터 Bottom Sheet | 모달(하단) | 기존 컨텍스트 유지 |
| 주문 확인 | 모달(중앙) | 의사결정 포커스 |
| Kill Switch 확인 | 모달(중앙) | 의사결정 포커스 |
| 공시 상세 | Push (스택) | 뒤로가기로 피드 복귀 |
| 기업 상세 | Push (스택) | 공시 상세→기업 상세 체인 가능 |
| 신호 상세 | Push (스택) | 피드 복귀 후 다른 신호 탐색 |
| Thesis 상세 | Push (스택) | 포지션→Thesis 체인 |
| 법적 문서 (약관 등) | Push (스택) | 읽고 돌아오는 패턴 |

---

### 4-6. 스크롤 위치 보존

**적용 규칙**:
- Push → 상세 → Pop: 리스트 스크롤 위치 복원 (React Navigation `automaticallyAdjustKeyboardInsets` + `FlatList` ref 활용)
- 탭 전환: 각 탭 스크롤 위치 유지 (`ScrollRestoration` 패턴 또는 `FlatList` 내부 상태)
- 검색 → 닫기: 검색 전 스크롤 위치로 복원

**`FlatList` 주의사항**:
- `windowSize`, `maxToRenderPerBatch` 설정으로 메모리 제어
- `getItemLayout` 제공 가능 시 반드시 제공 (스크롤 위치 복원 정확도 향상)

## 5. 리스트·피드 UX

### 5-1. 무한 스크롤 & 페이지네이션

**표준 구현**:
```
onEndReachedThreshold={0.3}   // 하단 30% 도달 시 다음 페이지 트리거
onEndReached={() => {
  if (hasNextPage && !isFetchingNextPage) fetchNextPage();
}}
ListFooterComponent={
  isFetchingNextPage
    ? <ActivityIndicator size="small" color={colors.primary} style={{paddingVertical: 16}} />
    : null
}
```

**페이지 크기**: 공시 20건, 신호 15건, 알림 30건 (서버 협의 필요)

**모든 데이터 로드 시**: 하단 "모두 확인했어요 ✓" 텍스트 (caption, textTertiary) — 선택적

### 5-2. 아이템 탭 영역

**전체 카드 탭 가능**: `TouchableOpacity`로 카드 전체를 감싸되, 카드 내부에 별도 액션 버튼이 있는 경우 버튼 탭이 카드 탭보다 우선.

**내부 버튼 탭 영역 분리 규칙**:
- BuyScoreCard: 카드 전체 탭 → 신호 상세 이동 + `[상세보기]` 버튼 탭 → 동일
- ExitScoreCard: `[Thesis]`, `[나중에]`, `[매도검토]` 각각 독립 탭 영역
- 공시 카드: 카드 전체 탭 → 공시 상세 + 기업명 탭 → 기업 상세

**탭 피드백**: `activeOpacity={0.7}` (기본. 0.5 이하 금지 — 너무 흐릿)

**롱프레스 (선택적)**:
- 공시 카드 롱프레스 → 컨텍스트 메뉴: [저장] [공유] [기업 상세]
- 신호 카드 롱프레스 → [관심목록 추가] [공유]
- 구현 복잡도 높으므로 P2 이후 도입 검토

---

### 5-3. 구분·그룹핑 UX

**공시 목록 날짜 구분**:
```
─────── 오늘 (2026.06.05) ─────────
[카드] [카드] [카드]
─────── 어제 (2026.06.04) ──────────
[카드] [카드]
```
- `SectionList` 또는 `FlatList` + 날짜 header 컴포넌트 (sticky header)
- 오늘 = "오늘", 어제 = "어제", 그 이전 = "YYYY.MM.DD"

**신호 피드 구분**: 날짜 구분 없음. 대신 `entryReady` 여부로 시각 구분:
- "진입 준비 완료" 섹션 상단 → "조건 미충족 신호" 섹션 하단 (또는 필터로 분리)

**주문 이력 날짜 구분**:
- 날짜별 섹션 헤더 (sticky)
- 같은 날 여러 건은 시간 순 정렬

### 5-4. 신호·공시 피드 필터 & 정렬 UX

**필터 Chip Row (스크롤 가능)**:
```
[전체] [공급계약] [자사주취득] [배당증가] [유상증자] [CB/BW]
          ← 스크롤 ←→
```

- 선택된 Chip: `contained`(primary 배경 + 흰 텍스트)
- 미선택: `outlined`(primary 테두리 + primary 텍스트)
- 복수 선택 가능 (OR 조건)
- `[전체]` 선택 시 다른 Chip 해제, 다른 Chip 선택 시 `[전체]` 해제
- 선택된 필터 수 > 0 시 필터 아이콘 우측에 배지 표시

**정렬 드롭다운 (공시 목록)**:
- 기본: 최신순 (default)
- 옵션: 최신순 / 오래된 순
- 드롭다운 위치: 목록 우상단 `feather:chevron-down` 버튼

## 6. 폼·입력 UX

### 6-1. 설정·알림 설정 폼 UX

**현재 알림 설정 화면 UX 개선 사항**:
- 토글 변경 즉시 서버 저장 (낙관적 업데이트)
- 저장 성공: 조용히 처리 (Snackbar 없음 — 너무 잦은 Snackbar는 노이즈)
- 저장 실패: Snackbar "설정 저장에 실패했어요. 다시 시도해 주세요." + 토글 롤백

**그룹별 설정 UX**:
```
알림 설정
────────
  전체 알림      [ON ●]   ← 마스터 스위치
  ────────────────────
  공시 알림      [ON ●]   ← 전체 OFF 시 비활성화 (dimmed)
    관심기업만   [ON ●]
    전체 공시    [OFF ○]
  ────────────────────
  매수 신호 알림 [ON ●]   (M6 이후 추가)
  EXIT 신호 알림 [ON ●]   (M8 이후 추가)
```

---

### 6-2. 검색 입력 UX 세부

**Debounce 설정**:
- 종목 검색: 300ms debounce
- 공시 검색: 500ms debounce (서버 부하 고려)
- 최소 입력 길이: 종목 검색 1글자, 공시 검색 2글자

**한글 조합 처리**:
```tsx
// 한글 입력 중 조합이 완료될 때만 API 호출
const [isComposing, setIsComposing] = useState(false);
<TextInput
  onChangeText={(text) => {
    if (!isComposing) debouncedSearch(text);
  }}
  // React Native에서 직접 compositionstart/end 이벤트 없음
  // → onChangeText에서 마지막 글자가 완성된 경우만 처리 (라이브러리 또는 조건 분기)
/>
```

실용적 대안: `onSubmitEditing`으로 검색 트리거 + 입력 중에는 로컬 필터링만.

**검색창 비우기 버튼**:
- 검색어 입력 시 우측에 `×` 버튼 표시 (`Searchbar`의 `onClearIconPress`)
- 탭 시 검색어 초기화 + 최근검색·인기종목 화면으로 복귀

---

### 6-3. 키보드 회피 (Keyboard Avoidance)

**표준 구현**:
```tsx
<KeyboardAvoidingView
  behavior={Platform.OS === 'ios' ? 'padding' : 'height'}
  style={{ flex: 1 }}
>
  <ScrollView keyboardShouldPersistTaps="handled">
    {/* 폼 내용 */}
  </ScrollView>
</KeyboardAvoidingView>
```

**`keyboardShouldPersistTaps="handled"`**: 스크롤 뷰 탭 시 키보드가 닫히지 않고 버튼·링크 탭이 작동하도록 — 검색 결과 아이템 탭이 키보드 닫기보다 우선.

**Bottom Sheet 키보드 처리**: Bottom Sheet 내 TextInput 포커스 시 Bottom Sheet 자체가 키보드 위로 올라와야 함 (라이브러리별 구현 확인 필요).

---

### 6-4. 포커스 플로우

**온보딩 검색 화면**: 진입 즉시 SearchBar 포커스 (`autoFocus`)
**공시 목록 검색 진입**: 탭 → SearchBar 포커스
**주문 승인 모달**: 모달 열림 시 [승인 →] 버튼으로 포커스 이동 (접근성)
**에러 재시도**: [재시도] 버튼 포커스 이동

## 7. 온보딩·첫 경험

### 7-1. 게스트 → 가입 전환 유도

**게스트 상태**: 로그인 없이 홈 피드·공시 목록 열람 가능.

**가입 유도 트리거**:

| 액션 | 유도 방식 |
|---|---|
| 알림 탭 탭 | "로그인하고 알림을 받아보세요" + [로그인] 버튼 (탭 내 빈 화면) |
| 관심기업 추가 시도 | "로그인 후 관심 기업을 추가할 수 있어요" Snackbar + [로그인] 액션 |
| 공시 저장 시도 | "로그인 후 공시를 저장할 수 있어요" Snackbar + [로그인] 액션 |
| 신호 탭 탭 (M6~) | "로그인하고 매수 신호를 받아보세요" + [로그인] 버튼 |
| 포트폴리오 탭 탭 (M7~) | "로그인하고 포트폴리오를 관리해 보세요" + [로그인] 버튼 |

**유도 패턴**: Snackbar의 `[로그인]` 탭 → 로그인 화면 (`router.push('/auth/sign-in')`)

### 7-2. 권한 요청 타이밍 (푸시 알림)

**현재 문제**: 권한 요청 시점이 너무 이름 (앱 진입 즉시 요청하면 거부율 높음).

**개선된 타이밍**:
1. 온보딩 완료(Persona 선택 후) → 알림 권한 요청 화면(온보딩D) — `"공시 알림을 받으시면 놓치는 공시가 없어요"`
2. 거부한 경우 → 홈 피드에서 첫 공시 카드 확인 후 (3~5분 이후) 소프트 배너로 재유도
3. 설정 > 알림 설정에서 언제든 권한 허용 유도

**소프트 배너**:
```
┌────────────────────────────────────────┐
│ 🔔 공시 알림을 받고 싶으신가요?       │
│    [설정에서 허용하기]        [닫기]  │
└────────────────────────────────────────┘
```
- 1회만 표시 (`expo-secure-store`에 표시 여부 저장)

### 7-3. 빈 관심목록 첫 안내

**최초 홈 피드 진입 + 관심기업 0개**:
```
┌────────────────────────────────────────┐
│    ⭐ 관심 기업을 추가해 보세요!        │  ← 강조 배너 (primaryLight 배경)
│  맞춤 공시와 분석을 받을 수 있어요     │
│  [관심 기업 추가하기 →]               │
└────────────────────────────────────────┘
```
- 관심기업이 1개 이상 추가되면 이 배너 사라짐 (영구적)
- `expo-secure-store`에 `hasWatchlistOnboardingShown=true` 저장 후 다시 표시하지 않음

### 8-3. Position / Thesis invalidConditions 가독성

**현재 문제**: `invalidConditions` 항목들이 추상적이거나 한 화면에 너무 많으면 스크롤해야 함.

**UX 개선**:
1. 최대 4개 항목 기본 표시, 추가 항목 `[N개 더 보기]` Accordion
2. 현재 위반(violated) 항목은 항상 최상단으로 고정
3. 각 항목 아이콘: 미위반=`feather:circle`(gray), 위반=`feather:x-circle`(error)
4. 위반 항목에 위반 발생 날짜 표시: "20일선 종가 이탈 (2026.06.04 위반)"

**훼손 조건 항목 필드 표시 표준**:
```
● 20일선 종가 이탈  [위반 2026.06.04]   ← feather:x-circle (red)
  ↳ "훼손 상태 — 매도 검토 권장"        ← 위반 시 보조 문구
○ 계약금액 축소 정정공시               ← feather:circle (gray)
○ 5거래일 내 거래량 급감               ← feather:circle (gray)
  (+ 1개 더)                          ← Accordion 닫힌 상태
```

## 9. 일관성·접근성

### 9-1. 터치 영역 규칙

**최소 44pt × 44pt** (모든 탭 가능 요소):
- 아이콘 버튼 (헤더 ←, ×, ★, 🔖): `hitSlop={{ top: 8, bottom: 8, left: 8, right: 8 }}`
- 목록 아이템 우측 Chevron (→): 아이템 전체 높이 최소 48pt
- `Chip`: 자체 높이 32pt → `hitSlop` 적용 또는 패딩으로 44pt 확보
- `Switch`: 기본 44pt 이상 (RN Paper 기본 충족)

**예외**: 인라인 텍스트 링크 ("전체보기", "더보기") → 최소 44pt 세로 확보가 어려운 경우 `paddingVertical` 조정

---

### 9-2. 로딩·비활성 상태 일관성

**비활성화(Disabled) 스타일 통일**:
- 버튼: `disabled={true}` → RN Paper 기본 비활성 스타일 (opacity 0.38)
- 토글/Switch: 전체 Switch 비활성 시 전체 컨테이너 `opacity={0.4}`
- 카드(BLOCKED 신호, 만료된 Thesis): 배경 `surfaceSecondary`, 텍스트 `textTertiary`

**로딩 중 버튼**: 탭 후 버튼 내 `ActivityIndicator` 표시, 중복 탭 방지 (`disabled={isLoading}`)

---

### 9-3. 다크 모드

**라이트/다크 자동 전환**: `useTheme()` 훅의 `isDark` 값으로 분기.

**다크 모드 주의 화면**:
- 그라디언트 헤더: `cardGradientStart`/`cardGradientEnd` 다크 버전 토큰 사용
- `GlassCard`: `intensity` 값을 다크 모드에서 조정 (너무 어두우면 30→20)
- AI 고지 `DisclaimerSection`: 다크 모드에서 `surfaceSecondary`가 충분히 구분되는지 확인

### 9-4. 스페이싱 리듬

**`theme/spacing.ts` 기준 사용**:

| 토큰 | 값 | 사용처 |
|---|---|---|
| `xs` | 4dp | 텍스트 간 미세 간격 |
| `sm` | 8dp | 아이콘-텍스트 간격, Chip 간격 |
| `md` | 12dp | 섹션 내 항목 간격 |
| `base` | 16dp | 표준 패딩, 아이템 세로 패딩 |
| `lg` | 20dp | 섹션 상단 간격 |
| `xl` | 24dp | 카드-카드 간격 |

**일관성 체크포인트**:

- 카드 내부 패딩: `spacing.base` (16dp) 통일
- 섹션 헤더 하단 간격: `spacing.md` (12dp)

### 9-6. accessibilityLabel 작성 기준

**수치 + 방향 명시** (색상만으로 전달 불가):
```
손익률 +2.04%  →  accessibilityLabel="수익률 2.04% 상승"
손익률 -3.2%   →  accessibilityLabel="수익률 3.2% 하락"
Buy Score 78   →  accessibilityLabel="Buy Score 78점, 매수 후보 수준"
Exit Score 72  →  accessibilityLabel="Exit Score 72점, 일부 축소 권장"
AI 비용 18.8%  →  accessibilityLabel="AI 비용 대 수익 비율 18.8%, 주의 구간"
```

**상태 명시** (아이콘만으로 전달 불가):
```
ThesisStatus [VIOLATED]  →  accessibilityLabel="Thesis 상태: 훼손. 매도 검토가 필요합니다"
북마크 아이콘 (저장됨)   →  accessibilityLabel="공시 저장됨. 탭하면 저장 해제"
★ 관심기업 (추가됨)      →  accessibilityLabel="관심목록에 추가됨. 탭하면 제거"
```

**버튼 액션 결과 명시**:
```
[승인 →]  →  accessibilityLabel="주문 승인 버튼", accessibilityHint="탭하면 확인 모달이 표시됩니다"
[Kill Switch]  →  accessibilityLabel="긴급 자동매매 중단 버튼", accessibilityHint="탭하면 자동매매가 즉시 중단됩니다"
```

## 10. AI 면책 UX

### 10-1. 표시 강도 계층

```
│     전적으로 투자자 본인에게 있습니다.     │
└────────────────────────────────────────────┘
```

- 화면 최하단 고정 (스크롤 가능 콘텐츠 아래 항상 표시)
- `accessibilityRole="text"`, `accessibilityLabel="투자 참고 정보 고지: 이 서비스는 투자 자문 서비스가 아닙니다"` (축약)

### 12-2. React Query 구현 주의사항

**낙관적 업데이트 (관심기업 추가/제거)**:
```tsx
const addToWatchlist = useMutation({
  mutationFn: (corpCode) => api.addWatchlist(corpCode),
  onMutate: async (corpCode) => {
    await queryClient.cancelQueries({ queryKey: ['watchlist'] });
    const previous = queryClient.getQueryData(['watchlist']);
    queryClient.setQueryData(['watchlist'], (old) => [...old, { corpCode }]);
    return { previous };
  },
  onError: (err, corpCode, context) => {
    queryClient.setQueryData(['watchlist'], context.previous); // 롤백
    showSnackbar('추가에 실패했어요. 다시 시도해 주세요.');
  },
  onSettled: () => {
    queryClient.invalidateQueries({ queryKey: ['watchlist'] });
  },
});
```

**주의**: `onMutate`에서 롤백 컨텍스트 반드시 반환. `onSuccess`에서 Snackbar 표시 (오류 Snackbar는 `onError`에서).

**Stale Time 설정 권고**:

| 데이터 | staleTime |
|---|---|
| 공시 목록 | 1분 |
| 공시 상세 | 5분 |
| 기업 정보 | 30분 |
| 관심목록 | 10분 |
| 현재가 | 30초 |
| 신호 목록 | 2분 |
| Thesis 상세 | 5분 |
| AI 비용 현황 | 5분 |
