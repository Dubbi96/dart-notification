# Claude 총괄 × paperclip 플릿 — 자율 고도화 운용 플레이북 (범용 템플릿)

> **이 문서는 프로젝트 무관 템플릿입니다.** 어떤 paperclip 프로젝트에도 그대로 드롭인하세요.
> `<...>` 표기는 프로젝트별로 치환할 값입니다. 특정 도메인/기능 언급을 의도적으로 배제했습니다.
>
> **무엇인가**: Claude Code(총괄/오케스트레이터)가 paperclip AI 멀티에이전트 플릿(구현)을 지휘해
> 코드베이스를 **자율·지속적으로 고도화**하는 운용 형상.

---

## 0. 한 줄 요약

> **Claude는 "두뇌"(감사·기획·검증·머지), paperclip 플릿은 "손"(구현)이다.**
> Claude는 직접 기능을 구현하지 않는다. 매 사이클 ① 완성된 PR을 검증·머지하고, ② 새 차원을
> 감사해 실결함만 이슈로 등록·디스패치하고, ③ 다음 사이클을 예약한다. 이 루프를 **수렴 없이**
> 돌린다. 단, **허위양성·패딩 없이 실제 결함만** 등록한다.

## 1. 2-레이어 멘탈 모델

두 개의 독립 레이어가 공존한다. 혼동 금지.

| 레이어 | 위치 | 읽는 주체 | 역할 |
|---|---|---|---|
| **Claude Code 네이티브** | `.claude/`(settings·hooks·agents) | Claude Code | 권한 경계·서브에이전트·총괄 두뇌 |
| **paperclip 오케스트레이션** | `.agents/`·`harness/`·`AGENTS.md` | paperclip 런타임 | 구현 플릿(PLANNER/DEVELOPER/REVIEWER/ORCHESTRATOR) |

- **Claude = 총괄**: 사람의 대리인. 무엇을 고칠지 **판단**, 결과를 **검증**, **머지**.
- **paperclip 플릿 = 구현 워커**: 이슈를 픽업해 격리 worktree에서 **구현**하고 PR을 올린다.

> ⚠️ **기능 개발·개선·고도화는 paperclip 플릿이 구현한다. Claude는 이슈 발행·할당·검증·머지만 한다.**
> (예외: 플릿 픽업 정체 + 사용자 명시 승인 시에만 Claude 직접 구현 — 일상 규칙 아님.)

## 2. 자율 루프 — 코어 엔진

매 사이클(한 번의 `/loop` 발화)은 **3단계**다. 이것이 전부다.

```
┌─────────────────────────────────────────────────────────────┐
│  ⏱️ 타임스탬프 (작업 시간 추적)                               │
│                                                               │
│  ① 수확(HARVEST)   in_review PR → 검증 → 머지                 │
│  ② 감사(AUDIT)     새 차원 1개 감사 → 실결함 이슈 등록 → 디스패치 │
│  ③ 예약(SCHEDULE)  다음 사이클 예약                           │
└─────────────────────────────────────────────────────────────┘
```

### ① 수확 (HARVEST)
1. **상태 조회**: 직전 배치 이슈가 `in_review`면 PR 완성.
2. **코드 리뷰**: PR diff — 의도대로인가, **금지영역(§6) 미접촉**인가.
3. **통합 빌드**: `verify/<batch>` 브랜치에 PR(들) 머지 → **충돌 확인**.
4. **DoD 게이트(§5)**: 타입체크 0 · 빌드 통과 · **테스트 그린(회귀 0)** · 린트 0.
5. **실기/에뮬 검증**(UI 변경 시): 결함이면 **반려(재이슈)**.
6. **working-tree 정합 검증** ⚠️ **(생략 금지)**: `git status --short | grep "^ ?D"` — 유실 추적파일 0.
7. **머지** → worktree·브랜치 정리 → 이슈 `done`.

### ② 감사 (AUDIT)
- 매 사이클 **이전과 다른 차원** 1개. (§4)
- **검증된 실결함만** 등록. 추측·코스메틱 금지.
- **파일별 1이슈**로 배치 등록(충돌 회피, §7) → 플릿 디스패치.

### ③ 예약 (SCHEDULE)
- 다음 사이클 예약(플릿 구현 시간 ~수십 분 확보).
- 같은 `/loop` 프롬프트를 그대로 전달해 반복.

## 3. 역할 & 경계 (RACI)

| 활동 | Claude 총괄 | DEVELOPER 플릿 | 사람 |
|---|---|---|---|
| 차원 감사·결함 발굴 | **R/A** | — | I |
| 이슈 명세·등록 | **R/A** | — | I |
| 기능 구현(코드 작성) | — | **R/A** | — |
| PR 리뷰·통합검증 | **R/A** | — | C |
| 실기/에뮬 검증 | **R/A** | — | — |
| 머지 결정 | **R/A** | — | C(위임 시) |
| 스키마 마이그레이션 **DB 적용** | C | — | **R/A**(휴먼게이트) |
| 시크릿/키 로테이션·안전 룰 변경 | — | — | **R/A**(휴먼게이트) |

- **Claude는 메인 브랜치에 직접 커밋하지 않는다** — 모든 변경은 플릿이 `feat/<id>-<slug>` + PR.
- **머지 = 사용자 최종승인이 원칙**, "검증→머지" 위임 시 Claude 수행(실기 검증 통과 전제).

## 4. 감사 차원(Audit Dimensions) — "수렴 금지"의 연료

한 차원을 다 보면 다음으로 이동한다. 프로젝트 특성에 맞게 가감하라.

**백엔드(기술)**
- 도메인 정확성(공식 중복·집계 모집단 불일치)
- 입력 검증(숫자 NaN/음수/무클램프 · 문자열 길이/형식 경계)
- 트랜잭션 원자성(복수 쓰기) · 동시성/TOCTOU(claim·advisory lock) · 스케줄러 멱등/오버랩
- 인덱스 커버리지(필터+정렬 복합) · 정렬 안정성(tie-break) · 조회 over-fetch(select 누락)
- 로깅 위생(시크릿 노출·표준 Logger) · 환경변수/시크릿 검증(fail-fast)
- 응답 계약 일관성(래퍼·에러 포맷·페이지네이션 메타)

**프론트(기술·UX)**
- 데이터 캐시/staleTime 일관성 · 인증 상태 위생 · 리스트 성능(메모이제이션)
- 접근성(터치영역·라벨·역할·선택상태·폰트스케일) · 빈상태/스켈레톤 일관성
- 에러 카피 행동유도성 · 카피 SSOT·자연스러움 · 날짜/시간 표기(정본·경계)
- 테마 토큰화(하드코딩 색상) · 텍스트 잘림 · 안전영역(노치) · 키보드/입력 UX

**제품/UX**
- 빈 데이터 첫사용자 동선 · 정보 위계·CTA 명확성 · 카피 SSOT 통합

> **차원이 고갈되는가?** 아니다. 기술이 성숙하면 **제품/UX·성능·접근성·관측성**으로 확장한다.
> "개선할 게 없다"는 거의 항상 **아직 안 본 관점이 있다**는 신호다.

## 5. 검증 규율(Discipline) — 이 형상의 핵심 가치

플릿이 빠르게 구현하므로, **Claude의 검증 품질이 전체 품질**을 결정한다.

### 5-1. 완료 정의(DoD) — 모든 머지의 통과 조건
1. 타입체크 0 · 빌드 통과
2. **테스트 그린(기존 테스트 회귀 0)** — *결정성을 위해 환경 고정(예: 타임존 `TZ=UTC`)으로 실행해 로컬 환경이 가리던 버그를 드러낸다.*
3. 스키마 변경 시 마이그레이션 커밋 + 키 정합
4. **금지영역 미침범**(§6)
5. **working-tree 정합**(유실 추적파일 0)
6. 변경 영역 문서 동기화

### 5-2. 허위양성·패딩 금지 — "LOW라도 실제만"
- **추측으로 이슈를 만들지 않는다.** 표면 패턴이 보여도 **실제 버그인지 코드로 검증**한 뒤 등록.
- 흔한 함정(반드시 끝까지 추적):
  - grep 매치가 **주석/문자열**일 수 있다(실제 사용 아님).
  - 비슷한 컴포넌트가 사실은 **다른 위젯**일 수 있다.
  - `add(..., { x })`가 사실 `{...SHARED_OPTS, x}` **spread**일 수 있다.
  - 로컬 시간 함수가 **생성+읽기 대칭**이면 타임존 안전일 수 있다.
- **"0건이 정답일 수 있다"** — 한 차원이 깨끗하면 정직하게 클린 판정하고 다음 차원으로.
- 단, **"개선할 게 없다"로 루프를 멈추지 않는다**(수렴 금지). 클린이면 차원을 바꾼다.

### 5-3. 코드베이스 자체 패턴과 비교 — 가장 강력한 발굴법
> 최고의 결함은 **"형제는 맞게 했는데 한 곳만 안 한" 불일치**에서 나온다.
> **기존 정본(canonical) 패턴을 찾고, 그것을 우회한 곳을 찾아라.**
- 예: N개 리스트 쿼리가 `select`로 경량화인데 한 곳만 전체 조회(over-fetch).
- 예: 다수가 `[정렬키, 유니크]` tie-break인데 일부만 단일키(페이지 중복/누락).
- 예: 다수 컴포넌트가 접근성 속성 적용인데 한 컴포넌트만 누락.

## 6. 금지영역(불가침) — 반드시 회피

| 영역 | 이유 | 대응 |
|---|---|---|
| AI 프롬프트/스키마·민감 비즈니스 로직 | 제품 핵심 IP·민감 | plumbing만, 내용 미접촉 |
| 안전·규제 하드룰(거래·결제·권한 등) | 안전·로드맵 게이트 | 미접촉 |
| 스키마 마이그레이션 **DB 적용** | 데이터 파괴 위험 | 파일 생성·커밋만, **적용은 사용자** |
| 시크릿/키 로테이션 | 비용·보안 | 휴먼 게이트 |
| force push · `rm -rf` · DB reset | 비가역 파괴 | **훅이 차단** |

- 매 PR 리뷰에서 `git diff --name-only`로 금지영역 접촉을 **명시 확인**.

## 7. 이슈 등록 & 배칭 — 충돌 회피 설계

### 7-1. 파일별 1이슈 원칙
- 여러 PR이 **같은 파일**을 수정하면 머지 충돌.
- 발견을 **파일별로 묶어** 한 이슈가 한 파일(또는 독립 파일 집합)만 건드리게.
- **공유 파일(테마·공통 카피·스키마 등)에 수렴하는 변경은 단일 이슈/단일 PR**로 묶는다.

### 7-2. 충돌 발생 시
- 같은 파일 다PR → **순차 머지**(rebase chain). **octopus 머지 금지.**
- 2회 차단된 PR → **닫고 새로 재구현**.
- 새 의존성 PR → 검증 전 패키지 설치.

### 7-3. 이슈 명세 포맷(플릿이 바로 구현 가능하게)
```
제목: <한줄 요약> (bug/perf/a11y/...)
본문:
  ## <심각도>: <한줄 문제>
  근거: <파일경로:라인> + 무엇이 왜 문제인지 구체적으로
  대조(정본): <같은 패턴을 올바르게 한 파일:라인>   ← 불일치형 결함에 강력
  해결: <1~2문장, 어느 파일만 건드릴지 명시>
  DoD: <단위/통합 테스트 기준> · 타입0 · 빌드 · 테스트 그린
  공통: DoD·금지영역·출처(배치·날짜)·"파일별 1이슈(충돌회피)"
```

## 8. paperclip API 연동 (템플릿)

> `<...>` 를 실제 값으로 치환. paperclip 로컬 런타임 기본 `http://127.0.0.1:<PORT>`(예 3100).

### 8-1. 엔드포인트
| 동작 | HTTP |
|---|---|
| 에이전트 목록(역할·ID 발견) | `GET /api/companies/<COMPANY_ID>/agents` |
| 이슈 목록 | `GET /api/companies/<COMPANY_ID>/issues?limit=<N>` |
| 이슈 생성 | `POST /api/companies/<COMPANY_ID>/issues` body `{title, description, assigneeAgentId, priority, workMode}` |
| 이슈 상태 변경 | `PATCH /api/issues/<ISSUE_ID>?companyId=<COMPANY_ID>` body `{status}`(`todo`/`in_progress`/`in_review`/`done`) |
| 에이전트 기동(픽업 유도) | `POST /api/agents/<AGENT_ID>/wakeup?companyId=<COMPANY_ID>` body `{message}` |

### 8-2. 역할/ID 발견 (신규 프로젝트 첫 단계)
```bash
curl -s "http://127.0.0.1:<PORT>/api/companies/<COMPANY_ID>/agents"
# → role 별 id 회수: PLANNER / DEVELOPER / REVIEWER / ORCHESTRATOR
# 구현 디스패치 대상 = DEVELOPER 의 id
```

### 8-3. 이슈 일괄 등록 스크립트 (Node, 템플릿)
```js
const C='<COMPANY_ID>', DEV='<DEVELOPER_AGENT_ID>', BASE='http://127.0.0.1:<PORT>';
async function api(m,p,b){const r=await fetch(BASE+p,{method:m,
  headers:{'content-type':'application/json'},body:b?JSON.stringify(b):undefined});
  return{s:r.status,j:await r.json().catch(()=>null)};}
const issues=[ /* {title, body, prio} ... */ ];
for(const it of issues){
  const rr=await api('POST',`/api/companies/${C}/issues`,
    {title:it.title,description:it.body,assigneeAgentId:DEV,priority:it.prio,workMode:'standard'});
  const i=rr.j.issue||rr.j;
  if(i?.id) await api('PATCH',`/api/issues/${i.id}?companyId=${C}`,{status:'todo'});
}
```
> ⚠️ 이슈 본문에 위험 명령 문자열(`migrate deploy/dev/reset`, `rm -rf` 등)이 있으면 권한 훅이
> bash 명령으로 오인·차단할 수 있다. **스크립트는 에디터/파일로 생성**(bash heredoc 회피),
> 본문엔 우회 표현(예: "표준 마이그레이션 절차") 사용.

## 9. 하드원 게쳐(Gotchas) — 실패에서 배운 것

1. **working-tree 유실** ⚠️ 최대 함정. 브랜치/worktree 조작(reset·remove) 후 추적 파일이
   working tree에서 삭제된 채 남을 수 있다. **매 머지 후 `git status --short | grep "^ ?D"` 필수.**
   복구는 `git checkout HEAD -- <경로>`. 놓치면 **"수렴했다"는 거짓 결론**에 이른다.
2. **권한 훅 오탐(heredoc)**: 이슈 본문의 위험 명령 **리터럴**이 차단될 수 있다 → 스크립트는 파일로 생성.
3. **테스트 환경 고정**: 로컬 환경(타임존·로케일)이 버그를 가린다. 검증은 **고정 환경**(예 `TZ=UTC`)으로.
4. **spread/변수 끝까지 추적**: 옵션 누락으로 단정 전, `{...SHARED, x}` 패턴인지 확인.
5. **실측 우선**: 접근성·레이아웃 등은 **추측 말고 실기/에뮬로 측정**(예 시스템 폰트 확대 후 확인).
6. **에뮬 네트워크**: 모바일 에뮬은 호스트를 특수 IP로 본다(`localhost` 아님). 인증 화면은 테스트
   계정 토큰을 딥링크로 주입해 검증.
7. **빌드 아티팩트 stale**: 생성형 클라이언트(예 ORM client) 변경 후 일시적 타입 실패는 코드 버그가
   아닐 수 있다. 공유 아티팩트 무단 재생성 금지, 머지 후 사용자 적용으로 검증.

## 11. 핵심 원칙 5줄 요약 (각인용)

1. **Claude는 두뇌, 플릿은 손** — 구현은 위임, 판단·검증·머지는 Claude.
2. **수렴 금지** — 클린이면 차원을 바꿔라. "개선 없음"은 거의 항상 안 본 관점.
3. **허위양성 금지** — 표면 패턴 말고 **코드로 검증한 실결함만**. LOW라도 실제만.
4. **정본 비교가 최강 발굴법** — 형제는 맞고 한 곳만 틀린 불일치를 노려라.
5. **working-tree 정합 + 고정환경 테스트** — 매 머지의 절대 게이트. 회귀 0을 지켜라.
