# DAR-570 — 19시 투자판단 에디션 종합 의견·투자 플랜

## 문제

19:05 에디션이 회사와 공시 카드를 바로 나열해 사용자가 아래 질문에 답하기 어려웠다.

1. 오늘 전체적으로 서두를 날인가, 확인할 날인가?
2. 어느 회사를 먼저 봐야 하는가?
3. 판단의 근거와 진입 전 확인 항목은 무엇인가?
4. 어떤 조건이면 계획을 중단해야 하는가?
5. 단기 계획을 세운다면 매수·청산 기준을 어떻게 잡는가?

## 결정한 정보구조

```
오늘/당시의 종합 의견
  ├─ 전체 판단·조건 준비·리스크 수
  └─ 먼저 볼 1순위

종목별 판단 카드
  ├─ 회사·공시 메타
  ├─ 판단: 조건부 검토 / 조건 확인 전 대기 / 리스크 확인 전 대기
  ├─ 판단 근거(최대 2줄)
  ├─ 지금/먼저 확인할 것(최대 2줄)
  └─ 조건 유지 시 단기 기준(준비 카드만)

상세 근거 → 기존 신호 상세
투자자문 아님 + 시나리오 맥락 고지
```

빈 에디션의 “주요 공시 브리핑”은 판단이 아니므로 기존처럼 별도 정보형 목록으로 유지한다.

## 판단 파생 규칙

- 모바일은 서버의 매수점수·필수 진입조건·리스크를 재계산하지 않는다.
- 필수 조건이 존재하고 모두 충족되며 리스크가 없을 때만 `조건부 진입 검토`.
- 미충족 필수 조건이 있으면 `조건 확인 전 대기`.
- 리스크가 하나라도 있으면 `리스크 확인 전 대기`를 우선한다.
- 조건 데이터가 없으면 준비 완료로 추정하지 않고 `근거 상세 확인`.
- 에디션 종합 의견은 위 종목별 결과의 개수를 정직하게 요약한다.
- 리스크가 있으면 미충족 조건보다 리스크 해소 확인을 먼저 제시한다.
- 대기·리스크 상태에서는 사용자가 숫자를 실행 신호로 오해하지 않도록 단기 수치를 숨긴다.

## 디자인 정밀 검토

### 발견한 문제

- 회사명과 상태 배지가 한 행에서 폭을 다퉈 긴 회사명이 잘리고 점수가 어색하게 줄바꿈됐다.
- 판단 근거·진입 조건·중단 조건·4칸 시나리오가 모두 펼쳐져 첫 카드가 360px에서 약 618px까지 늘어났다.
- 미충족 조건이 `진입 전 확인`과 `계획 중단 기준`에 반복됐다.
- 조건 미충족·리스크 카드에도 +10%/-5%/5거래일 수치가 노출돼 “대기”보다 숫자가 먼저 읽혔다.
- 좁은 폭에서 단기 수치가 2열+1열로 갈라져 정렬감이 깨졌다.

### 적용 원칙

- `종합 의견 → 상태 → 근거 → 다음 행동 → 조건부 수치` 순으로 읽도록 단계적 노출한다.
- 회사명은 최대 2줄, 메타는 한 줄 말줄임, 상태는 독립 행으로 분리한다.
- 근거와 행동은 화면에서 각각 최대 2줄만 보이고, 전체 판단 근거는 카드 접근성 라벨과 상세 화면에 유지한다.
- 단기 수치는 `조건 충족 + 리스크 없음 + 점수 40 이상`일 때만 노출한다.
- 단기 수치 3개는 320px에서도 고정 3열을 유지한다.

### 실렌더 결과

| 조건 | 결과 |
|---|---|
| 360×800, 긴 회사명·긴 근거 | 첫 카드 405px, 대기/리스크 320px, 가로 오버플로 0 |
| 수정 전 대비 | 첫 카드 618px → 405px, 약 34% 감소 |
| 320×700 | 가로 오버플로 0, 수치 3열 유지 |
| 글자 1.5배 + 320px | 회사명 2줄·메타 한 줄 말줄임, 상태/화살표 충돌 0 |

## 가격 표현 결정

19시에는 다음 거래일 실제 시가를 알 수 없으므로 당일 종가를 확정 매수가처럼 제시하거나 임의의 절대 목표가를 만들지 않는다. 기존 정본 전략 중 공시 매수등급과 연결 가능한 `short-momentum`만 “단기 참고 시나리오”로 표시한다.

| 기준 | 값 |
|---|---:|
| 적용 점수 | 매수점수 40 이상 |
| 진입 | 다음 진입 가능 거래일 시가, 조건 재확인 |
| 청산 참고 | 실제 체결가 대비 +10% |
| 중단 | 실제 체결가 대비 -5% |
| 최대 기간 | 5거래일 |

값은 `backend/src/engine3-quant-market/backtest/strategies/strategy-presets.ts` 정본과 Jest에서 직접 대조한다. 향후 절대 원화 가격을 표시하려면 “실제 체결가 입력 또는 체결 연동”과 가격 데이터 기준일·출처를 함께 제공해야 한다.

## 검증 범위

- 종합 의견과 종목별 판단 파생 순수함수 단위 테스트
- 조건 충족·미충족·리스크·조건 결측·과거 에디션 분기
- 에디션 실제 컴포넌트 렌더와 상태별 가격 시나리오 표시/숨김
- 백엔드 short-momentum 정본 드리프트 검사
- 결정론적 밀도 검사(`check-edition-decision-density.ts`)
- TypeScript·ESLint·전체 Jest·Android export

- 종합 의견/플랜 카드별 열람·상세 전환 계측
