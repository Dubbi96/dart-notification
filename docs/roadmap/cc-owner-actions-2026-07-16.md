## ① Google Play 개발자 계정 등록($25) + 테스터 12명×14일 클록 기동

**무엇을** — 개인 Google Play 개발자 계정을 등록하고($25 1회), 현행 oci 프로파일 빌드를 클로즈드 테스트 트랙에 올린 뒤 테스터 12명을 모집해 **연속 14일 테스트 클록**을 기동한다. 동시에 `eas submit` 배관 완성을 위해 Play Console API 서비스 계정 키(`google-service-account.json`)를 발급해 EAS 파일 시크릿으로 주입한다.

**왜** — 신규 개인 계정은 테스터 12명×연속 14일 클로즈드 테스트를 통과해야 production 트랙이 열린다(순수 캘린더 시간 — 돈·코드로 단축 불가). M10 졸업(≈8/5)과 **동시 공개**하려면 역산상 지금 시작해야 한다: 7/22 클록 기동 → 8/5 클록 종료, 심사 리드타임(1~4주)은 클록과 병행. 사이드로드 APK는 설치 전환율을 죽이는 신뢰 킬러이자 stale 배포 사고(6/25 실재)의 구조적 원인이다. `mobile/eas.json`에는 submit 배관(`serviceAccountKeyPath: ./google-service-account.json`, track: internal)이 이미 있으나 **키 파일 자체가 실존하지 않는다** — 발급은 오너 콘솔 권한.

**비용** — $25(1회, 카드 결제). **소요** — 계정 등록·신원 인증 1~2시간(승인 대기 1~3일), 서비스 계정 발급 30분, 테스터 모집이 실물 병목(지인·투자 커뮤니티). **마감 권고** — 계정 등록 7/17, 테스터 클록 기동 7/22.

**따라하기 절차**

1. **계정 등록**: [play.google.com/console/signup](https://play.google.com/console/signup) → 개인(Individual) 계정 선택 → $25 결제 → 신분증 신원 인증(승인 1~3일 소요, 여기서 지연되면 전체 일정 밀림 — 오늘 착수).
2. **앱 생성**: Play Console → 앱 만들기 → 앱 이름 "공시온", 패키지 `com.gongsion.app`(앱 서명 키는 Play App Signing 사용 — 기존 사이드로드 키와 분리됨, 자동 이관 불가는 알려진 트레이드오프).
3. **서비스 계정 키 발급** (`eas submit` 배관 완성):
   - Play Console → 설정 → API 액세스 → Google Cloud 프로젝트 연결 → 서비스 계정 만들기(역할: 서비스 계정 사용자).
   - Google Cloud Console → 해당 서비스 계정 → 키 → JSON 키 생성 → `google-service-account.json` 다운로드.
   - Play Console → API 액세스 → 해당 서비스 계정에 권한 부여(릴리스 관리 권한).
4. **EAS 파일 시크릿 주입** (FCM `google-services.json`과 동일 패턴 — 2026-06-26 전례):
   - 로컬: 파일을 `mobile/google-service-account.json`에 두되 **git 커밋 절대 금지** — `.gitignore` 포함 여부 먼저 확인(`git check-ignore mobile/google-service-account.json`이 경로를 출력해야 함. 미포함이면 플릿에 gitignore 추가 이슈 1건 발행).
   - EAS 시크릿 등록: `cd mobile && eas env:create --scope project --name GOOGLE_SERVICE_ACCOUNT_KEY --type file --value ./google-service-account.json` (EAS CLI 버전에 따라 `eas secret:create --type file`). 로컬 `eas submit`은 `eas.json`의 `serviceAccountKeyPath`가 로컬 파일을 직접 읽으므로 로컬 보관본만으로도 동작 — 시크릿 등록은 유실 대비 백업 겸용.
5. **클로즈드 테스트 트랙 업로드**: 현행 oci 프로파일 AAB/APK를 내부 테스트(internal) 또는 비공개 테스트(closed) 트랙에 업로드. production 승격 요건 클록은 **비공개 테스트 트랙** 기준이므로 비공개 트랙 생성 → 테스터 이메일 리스트(또는 Google 그룹) 등록 → opt-in URL 확보.
   - 주의: production 프로파일의 `EXPO_PUBLIC_API_URL`이 사멸한 AWS ALB를 가리키는 문제는 플릿 코드 이슈로 별도 수정(오너 작업 아님) — 수정 머지 전에는 oci 프로파일 기반 빌드를 올릴 것.
6. **테스터 12명 모집·클록 기동**: 지인·투자 커뮤니티에서 실사용 테스터 모집(허위 테스터는 정책 위반 = 계정 정지 리스크). 12명 전원 opt-in 완료 시점부터 연속 14일 카운트 — **7/22까지 12명 opt-in 완료**가 목표. 테스터 코호트는 M10 관찰 데이터 수집(도그푸딩)과 겸용.
7. **병행 준비(플릿 배분, 오너는 발행만)**: 계정 삭제(탈퇴) 엔드포인트(Play 하드 요구사항), 개인정보처리방침 공개 웹 URL, 금융기능 선언서 초안(기존 `docs/work/m0/policy-non-advisory.md` 재활용) — 각 DAR 이슈 발행.
8. **기록**: 클록 기동일·테스터 명단·opt-in 현황을 이 문서 하단 진행 로그에 기록.

## ② 실도메인 구매(~$12/년) + 컷오버 체크리스트

**무엇을** — 실도메인(예: `gongsion.app` 또는 `.kr`, ~$10~15/년)을 구매하고, Caddy에 vhost를 추가해 신도메인 HTTPS를 확보한 뒤, 카카오 redirect URI를 **3곳 동시 교체**하고 APK를 재빌드한다. **nip.io는 병행 유지**(제거 금지).

**왜** — `168.138.198.152.nip.io`는 IP가 그대로 박힌 무료 도메인이라 (a) OCI IP 회수 시 앱·카카오 로그인이 동시 사망하는 단일 실패점, (b) 금융 서비스 첫인상 신뢰 결격 + 보안 솔루션 차단 리스크, (c) 스토어 리스팅 신뢰 표면 결격이다. 도메인 구매·DNS·레지스트라 계정·카카오 개발자 콘솔은 전부 오너 권한. **6/24 카카오 302 장애 전례**: redirect URI 교체 누락 시 로그인 전면 장애.

**비용** — ~$10~15/년(.kr ~₩20,000/년). TLS는 기존 Caddy + Let's Encrypt로 $0. **소요** — 구매·DNS 10분, 컷오버 1~2시간. **마감 권고** — 구매 7/18, 컷오버 7월 말(반드시 장외 시간 — M10 측정 무오염).

**따라하기 절차**

1. **구매**: 레지스트라(Cloudflare Registrar·Namecheap·가비아 등)에서 도메인 구매 → DNS A 레코드: `@`(및 필요 시 `api`) → `168.138.198.152`.
2. **Caddy vhost 추가** (micro1, ssh 키 `~/.ssh/oci_instance`):
   - `ssh -i ~/.ssh/oci_instance ubuntu@168.138.198.152` → Caddyfile에서 기존 `168.138.198.152.nip.io` 블록을 **유지한 채** 신도메인 블록을 동일 reverse_proxy 설정으로 1블록 추가 → `caddy reload`(또는 Caddy 컨테이너 재기동). Let's Encrypt 발급은 Caddy가 자동 처리.
   - 검증: `curl -sSf https://<신도메인>/api/health` 200 확인. **nip.io도 계속 200이어야 함** — 사이드로드 구버전 APK는 강제 업데이트 채널이 없어 nip.io를 계속 때린다. 컷오버가 아니라 **병행 기간 개시**다.
3. **카카오 redirect URI 3곳 동시 교체** (하나라도 누락 = 로그인 전면 장애, 6/24 전례):
   - (1) **카카오 개발자 콘솔**: [developers.kakao.com](https://developers.kakao.com) → 앱 → 카카오 로그인 → Redirect URI에 `https://<신도메인>/api/auth/kakao/callback` **추가**(기존 nip.io URI는 병행 기간 동안 삭제 금지).
   - (2) **prod env**: 원격 `.env`의 카카오 redirect/콜백 관련 값 및 `CORS_ALLOWED_ORIGINS`에 신도메인 반영 → env 변경은 재시작으로 반영 안 됨: `docker compose -f /home/ubuntu/dano/docker-compose.yml up -d --force-recreate app` (6/24 전례 — force-recreate 필수).
   - (3) **mobile/eas.json**: oci(및 production) 프로파일 `EXPO_PUBLIC_API_URL`을 `https://<신도메인>/api`로 교체 — 코드 변경이므로 플릿 이슈로 발행해도 되나, 오너가 직접 하면 1줄 수정 + PR.
4. **APK 재빌드·배포**: 신 URL 반영 빌드 1회(`eas build --profile oci --platform android`) → Play 클로즈드 트랙에 업로드(①과 합류 — 테스터에게는 신도메인 빌드 배포).
5. **배포 타이밍**: 재기동을 동반하는 2-(2) 단계는 반드시 장외(15:30 이후, 권장 주말) — 모의매매 사이클(체결=예약→익일시가)·라이브 수집과 겹치면 측정 오염.
6. **병행 종료 조건 기록**: 사이드로드 사용자 전원이 스토어 빌드로 이관 확인된 후에만 nip.io vhost·카카오 구 URI 제거(당분간 무기한 병행).

## ③ UptimeRobot 외부 사망감시 설정

**무엇을** — UptimeRobot 무료 티어로 `https://168.138.198.152.nip.io/api/health`를 5분 간격 폴링하는 외부 모니터를 만든다.

**왜** — 내부 모니터(data-freshness-monitor, OPS_ALERT 푸시)는 **서버 자체가 죽으면 못 운다**. 외부 사망감시가 $0·10분으로 이 맹점을 커버한다. 외부 SaaS 계정 생성·알림 수신처 등록은 오너 권한.

**비용** — $0 (무료 티어: 모니터 50개·5분 간격). **소요** — 10분. **마감 권고** — 오늘(7/16).

**따라하기 절차**

1. [uptimerobot.com](https://uptimerobot.com) 가입(무료 플랜).
2. Add New Monitor → Monitor Type: **HTTP(s)** → URL: `https://168.138.198.152.nip.io/api/health` → Interval: **5 minutes**.
3. Alert Contacts: 오너 이메일 등록(무료 티어 기본). 선택: UptimeRobot 모바일 앱 설치 시 푸시 알림 추가.
4. 검증: 모니터 상태 "Up" 확인. (의도적 다운 테스트는 프로드라 생략 — 첫 실제 장애 시 알림 도달 확인.)
5. ② 컷오버 후 신도메인 `https://<신도메인>/api/health` 모니터를 **추가**(nip.io 모니터는 병행 기간 동안 유지 — 두 진입점 각각 감시).

## ④ 프로드 JWT 시크릿 로테이션 런북

**무엇을** — 프로드 `JWT_SECRET`·`JWT_REFRESH_SECRET` 2키를 64바이트 랜덤 값으로 로테이션하고, 절차를 런북화해 분기 1회 드릴로 굳힌다.

**왜** — 로컬 dev 시크릿이 27/35자 수준이고 **프로드 실값 강도는 미검증**이다. 카카오 신원+포트폴리오를 보유한 금융 앱이 스토어로 공개되기 전에 완결해야 한다. 재로그인 비용은 사용자=오너 1인이라 사실상 0 — 지금이 최저비용 시점. 원격 `.env` 접근·배포 윈도우 결정은 오너 권한. **반드시 장 마감 후 실시** — 라이브 수집·모의매매 사이클과 겹치면 신호 유실(7/15 파싱 기아 직후라 수집 파이프 민감).

**비용** — $0. **소요** — 30분. **마감 권고** — 7월 내, 다음 장외 배포 윈도우(15:30 이후, 권장 주말. ②의 force-recreate와 같은 윈도우로 묶으면 재기동 1회로 합산 가능).

**따라하기 절차**

## ⑥ KRX 서면질의 발송

**무엇을** — KRX 시세·지수 데이터의 서비스 내 이용·재배포 범위(무료 제공·유료화 시 각각)에 대한 서면질의를 KRX에 발송한다. 초안은 `docs/compliance/krx-inquiry-draft`(컴플라이언스 레인 산출물 — 미머지 상태면 해당 레인 산출물 회수 후 발송).

**왜** — 유료화(M12) 시 KRX 데이터 이용 조건은 서비스 존속 리스크인데, **회신에 수 주가 걸리는 순수 캘린더 시간**이다. M10 졸업(≈8/5) 후 유료화 논의 전에 답을 받으려면 지금 발송해야 한다. 회사(개인사업자) 명의 대외 서신은 오너만 가능.

**비용** — $0. **소요** — 초안 검토·발송 30분. **마감 권고** — 이번 주(7/18) 발송.

**따라하기 절차**

1. **초안 확보**: `docs/compliance/krx-inquiry-draft` 확인 — 없으면 컴플라이언스 레인에 초안 요청. 핵심 질의 골자: (a) 공개 웹(data.krx.co.kr) 일봉·지수 데이터의 앱 내 재표시 허용 범위, (b) 무료 서비스 vs 유료 서비스에서의 조건 차이, (c) 시세 데이터 재배포 계약 필요 여부·비용 체계, (d) 출처 표기 요건.
2. **발신 정보 정리**: 서비스명(공시온)·용도(공시 알림+투자 판단 참고, 현재 무료 베타)·데이터 사용 방식(일봉·지수 조회 표시, 재판매 없음)을 사실대로 기재.
3. **발송 채널**: KRX 정보데이터시스템(data.krx.co.kr) → 고객지원 문의 접수, 또는 KRX 데이터 사업 부서 공식 이메일. 서면 회신을 명시적으로 요청(구두 답변은 근거 불충분).
4. **기록**: 발송일·채널·질의 사본 위치를 진행 로그에 기록.
5. **팔로업**: 3주 무회신 시 재문의. 회신 수령 시 `docs/compliance/`에 원문 보관 + M12 유료화 게이트 결정 입력값으로 등록.

## ⑧ 금융소비자보호 교육 온라인 이수

**무엇을** — 금융소비자보호 관련 온라인 교육 과정을 이수한다(수 시간, 무료).

**비용** — $0 (온라인 과정 기준. 신고 시점에 수수료·이수 유효기간 등 최신 요건 재확인 필요 — 이수 유효기간 요건이 있으면 신고 직전 재이수가 안전). **소요** — 수 시간. **마감 권고** — 8월 중(M10 졸업 후 유료화 결정 전).
