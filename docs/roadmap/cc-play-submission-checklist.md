## 1. 개인정보처리방침 URL

**현황 — 이미 공개 웹 URL로 게시됨:**
- `backend/src/legal/legal.controller.ts` → `GET /api/legal/privacy` (인증 불요, `Content-Type: text/html`, Swagger 문서 제외).
- 실제 접근 URL: `https://168.138.198.152.nip.io/api/legal/privacy` (현재 API 도메인 기준. `mobile/eas.json`의 `play` 프로파일도 동일 `EXPO_PUBLIC_API_URL` 사용).
- 내용은 인앱 화면 `mobile/app/legal/privacy.tsx`와 동일(카카오 프로필 수집 항목·보유기간·제3자 위탁(AWS/Expo)·이용자 권리 등 9개 항목 명시, 시행일 2026-03-09).

**점검 필요:**
- ⚠️ 현재 도메인은 IP 기반 임시 도메인(`nip.io`). `cc-pm-cycle1-plan-2026-07-17.md` §5-2에 따르면 7월말 실도메인 구매·컷오버 예정 — 컷오버 후 Play Console에 등록한 URL이 죽은 링크가 되지 않도록 **URL 재등록이 필요**(오너 후속 액션, 컷오버 PR과 함께 트리거).
- 최초 제출은 nip.io URL로 진행 가능(Play는 URL이 "공개적으로 접근 가능"하면 되고 브랜드 도메인을 요구하지 않음).
- `legal-content.ts` 주석에 "본문 수정 시 privacy.tsx와 양쪽 동기화 필수"라고 명시되어 있음 — 향후 정책 문구 변경 시 두 파일 동시 수정 규율 유지.

**오너 액션:** Play Console → 앱 콘텐츠 → 개인정보처리방침 → 위 URL 붙여넣기.
**PM 액션:** 완료(URL 존재·내용 확인). 도메인 컷오버 시 재등록 알림 발행 예정.

## 2. 계정 삭제(회원탈퇴) — Play 하드 요구사항

**현황 — 인앱 경로 + 웹 공개 경로 이중 구현됨(갭분석 W3):**
- 인앱: `DELETE /users/me`(`users.controller.ts` `deleteMe`) + FE `mobile/app/settings-detail/profile.tsx`의 "회원 탈퇴" 플로우(2단계 확인 다이얼로그 → `useDeleteAccount` → 세션 초기화·로그인 화면 이동).
- 웹 공개 안내: `GET /api/legal/account-deletion` — 인앱 삭제 절차 + 이메일 삭제 요청 경로(`support@gongsion.com`) + 삭제 데이터 범위(계정정보·관심기업·알림이력·포트폴리오·기기토큰·세션 전부) + 법정 보존 예외 고지.

Play 정책은 "앱 내 삭제 경로"와 "웹에서도 삭제 요청 가능"을 모두 요구하며 위 구현이 둘 다 충족한다.

**오너 액션:** Play Console → 앱 콘텐츠 → 데이터 삭제 → `.../api/legal/account-deletion` URL 등록 + "앱 내에서도 계정 삭제 가능" 체크.
**PM 액션:** 완료(구현·문구 확인).

## 3. 금융 기능 선언 (Financial Features declaration)

**중요 전제 — 첫 게시 빌드는 "거래 실행" 기능이 없다:**
DAR-549(2026-07-17 병합, 오너 결정)로 `play` 프로파일 빌드는 `EXPO_PUBLIC_SHOW_TRADING=false`로 다음을 전면 숨긴다:
- 포트폴리오 탭(5탭→4탭 IA, `href: null`)
- 트레이딩 라우트 6종(`auto-trading`·`trade-history`·`backtest-track-record`·`strategy/*` 등) — 진입/딥링크 시 홈으로 리다이렉트(`withTradingGuard` HOC)
- 홈 화면 '운용 성과' footer(GraduationTracker)
- 신호 카드의 모의매매 진입점

즉 이 빌드에서 사용자가 실제로 접할 수 있는 기능은 **공시 알림 + AI 요약 + Buy Score/유사공시 반응 통계(정보 제공)** 뿐이며, 매매 실행·주문·모의투자 진입점은 물리적으로 존재하지 않는다(`mobile/scripts/check-trading-gate.ts` 29개 단언으로 결정론 검증됨).

**선언 가이드(오너 확인 후 콘솔 입력):**
| Play 질문 | 권장 응답 | 근거 |
|---|---|---|
| 금융 서비스/상품 제공 여부 | 예 — "투자 정보 제공" | 공시 요약·Buy Score·EventStudy 통계는 정보 제공에 해당 |
| 거래 실행/중개/대출/보험/결제 서비스 | 아니오 | `play` 빌드에서 전면 게이팅됨(위) |
| 인앱 결제/유료 구독 | 아니오 | Pro waitlist는 대기자 등록만(결제 코드 0줄) |

**비자문 고지 문구(`plan-policy.md` 정본, 스토어 설명·앱 내 고지에 일관 사용 권고):**
> "본 서비스는 투자자문업이 아닙니다. 제공되는 분석 리포트·공시 요약·Buy Score는 투자 판단의 참고 자료로만 활용하시고, 최종 투자 결정과 그에 따른 손익은 투자자 본인에게 있습니다."

**오너 액션:** Play Console → 앱 콘텐츠 → 금융 기능 선언 폼에 위 가이드대로 입력(콘솔 UI는 PM 접근 불가 — 실제 입력은 오너 전담).
**PM 액션:** 선언 문구·근거 제공(완료). 후속 릴리스에서 모의투자/자동매매 게이트 해제 시 **재선언 필요**함을 게이트 백로그에 기록 권고.

## 4. 데이터 안전 섹션 (Data safety form)

**수집 데이터 매핑(코드 근거):**
| 데이터 유형 | 항목 | 수집 근거 | 목적 |
|---|---|---|---|
| 개인 식별자 | 카카오 고유 ID, 이름(닉네임), 이메일 | `privacy.tsx` §1 필수항목, 카카오 OAuth | 회원 식별·인증 |
| 기기·기타 ID | 기기 식별자, OS 버전, Expo Push Token | `privacy.tsx` §1 자동수집항목 | 푸시 발송·기기 관리 |
| 앱 활동 | 관심목록·알림설정 등 이용기록 | `privacy.tsx` §1 | 맞춤 알림 제공 |
| 앱 활동(분석용) | 인앱 행동 이벤트 8종(`edition_open`/`card_tap`/`push_open`/`stats_section_view`/`waitlist_cta`/`survey_ios_*`) | `TesterEvent`(DAR-516, `backend/src/ops/dto/record-tester-event.dto.ts`) | 테스터 코호트 오픈율·재방문 측정 |

**PII 무수집 확인:** `TesterEvent`는 `userId`(내부 인증 ID)·`event`(고정 화이트리스트)·서버 타임스탬프 3필드뿐이며, `IsIn` 검증으로 자유텍스트·종목코드 등 식별정보가 이벤트명에 실리는 것을 입력 단에서 차단한다(`docs/analytics/tester-cohort-instrumentation.md` §3). 위치정보·연락처·사진·건강정보 등은 미수집.

**제3자 공유:** AWS(서버 호스팅·데이터 저장), Expo(푸시 알림 발송) — `privacy.tsx` §5 명시. 광고 SDK·트래커 없음.

**Data Safety 폼 매핑 가이드:**
- "개인 식별자" 수집 = 예(이름/이메일, 계정관리 목적, 필수) → 공유 안 함(제3자 마케팅 미공유).
- "기기 또는 기타 ID" 수집 = 예(앱 기능 목적).
- "앱 활동"(인앱 행동) 수집 = 예(분석 목적, 제3자 미공유).
- 데이터 암호화 전송(HTTPS) = 예 — 전 구간 `https://` 스킴(eas.json 전 프로파일 확인). 단, TLS 종단(Caddy 추정, `cc-live-readiness-diagnosis-2026-07-03.md` OPS-6 "Caddy·DB 기동 비코드화")이 IaC로 코드화되어 있지 않아 **오너가 제출 직전 `curl -I https://<API 도메인>/api/health`로 실측 확인 권고**.
- 데이터 삭제 요청 가능 = 예(§2 경로).

**오너 액션:** Play Console Data Safety 설문 실제 입력(위 매핑표 그대로 반영).
**PM 액션:** 매핑표 제공(완료). 향후 신규 데이터 수집 추가 시(예: 모의투자 게이트 해제, 결제 도입) 재점검 필요.

## 5. 스크린샷 규격

**기준 버전:** `play` 프로파일 빌드 = **4탭 IA**(홈/알림/신호/설정). 이슈에서 언급한 "4탭 게이팅 버전"은 DAR-549의 이 빌드를 가리키는 것으로 확인됨(포트폴리오 탭이 숨겨져 실제 탭 수가 5→4로 줄어듦).

**Play 규격(휴대폰 스크린샷):**
- 최소 2장 ~ 최대 8장.
- 비율 16:9 또는 9:16, 각 변 320px~3840px, JPEG 또는 24-bit PNG(알파 채널 없음).

**권장 촬영 대상(5장, `play` 빌드 기준):**
1. 홈 탭 — 최신 에디션 요약 카드(`HomeSignalPreview`). ⚠️ '운용 성과' footer(GraduationTracker)가 렌더되지 않는지 확인(트레이딩 게이팅 대상).
2. 알림 탭 — 통합 인박스(공시/신호/청산 알림).
3. 신호 탭 — 에디션 브라우징(`BuyEditionView`).
4. 공시 상세 — AI 요약 + '과거 유사공시 반응' 통계 섹션(`DisclosureReactionSection`, 핵심 셀링포인트).
5. 설정 탭 — 알림 설정 센터(v2, 5계열 on/off).

**주의:** 포트폴리오·모의매매·자동매매·백테스트 트랙레코드 화면은 이 빌드에서 접근 불가(딥링크 시도해도 홈으로 리다이렉트) — **구버전(5탭) 스크린샷을 재사용하면 실제 앱과 리스팅이 불일치**하게 되므로 반드시 `play` 프로파일로 빌드한 실물에서 새로 촬영해야 한다.

**오너 액션:** `eas build --profile play --platform android` 결과물을 실 기기/에뮬레이터에 설치 후 위 5개 화면 촬영.
**PM 액션:** 촬영 대상·순서 제공(완료). 사전 검증: `cd mobile && npx tsc scripts/check-trading-gate.ts ... && node scripts/check-trading-gate.js`(29단언 전부 pass 확인 후 촬영하면 트레이딩 표면 노출 실수를 방지).

## 6. 앱 서명 · AAB 여부

**현황 — AAB는 이미 배관 완료:**
- `mobile/eas.json` `play` 프로파일: `"android": { "buildType": "app-bundle" }` — Play가 2021년 8월부터 신규 앱에 요구하는 AAB 포맷을 이미 충족.
- 반대로 `oci`/`preview` 프로파일은 사이드로드용 `apk` — **Play 제출에는 절대 사용하지 말 것**(스토어용은 `play` 프로파일 전용).
- 앱 서명: Play App Signing 사용 예정(`cc-owner-actions-2026-07-16.md` ①에 이미 기재) — 기존 사이드로드 서명 키와는 별개 키가 되며 자동 이관 불가는 알려진 트레이드오프.

**갭(제출 전 해소 필요):**
1. `eas.json`의 `submit.production` 블록만 존재하고 **`submit.play` 블록이 없음** — `eas submit --profile play`를 바로 쓸 수 없다. 최초 제출은 Play Console UI에 AAB를 수동 업로드하는 방식으로 우회 가능하나, 향후 자동화하려면 `submit.play`(serviceAccountKeyPath + track) 추가가 필요(코드 1줄 변경, 별도 소이슈로 위임 검토 — 이번 이슈 범위(docs만) 밖).
