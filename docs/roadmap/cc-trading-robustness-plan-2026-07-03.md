# 시스템 트레이딩 견고화 계획 정본 (2026-07-03)

> **목적**: 외부 참조 문서 2건(전략 총람 룰북·한투API 구현명세)의 견고성 기준으로 현 시스템을 전수 감사하고,
> 리팩토링/전면 재설계의 타당성을 판정한 뒤, 견고화 실행 계획을 확정한다.
> **판정 결론: 전면 재설계 불타당 — 현 5엔진 아키텍처 유지 + 증축(incremental-extension) 채택. 조건부 상향 트리거 4종 명시.**
>
> 작성: Claude Code (멀티에이전트 감사 24 에이전트: 5영역 병렬 감사 → high 갭 14건 전수 반박검증 → 증축안/재설계안 독립 설계 → 심판 판정)
> 선행 정본: `cc-live-readiness-diagnosis-2026-07-03.md`(1차 웨이브·§8-1 클록 리셋), `buy-logic-validation-baseline.md`, `cc-mvp-definition.md` §9

## 0. 입력과 질문

**외부 참조 문서** (사용자 제공, 저장소 외부):
1. **시스템 트레이딩 전략 총람 (Rule Book)** — 고전 검증 전략들의 정량 규칙 + **8장 포지션사이징·리스크 공통모듈**(고정비율 2%룰·ATR 사이징·변동성 타게팅·손절 카탈로그·계좌레벨 한도) + **9장 검증 체크리스트**(백테스트 6대 함정·전략 유형/타임프레임 분산·실전 이행 7단계).
2. **구현명세서 (한국주식×한투API)** — 2단 구조: **코어(60~70%) 한국형 듀얼모멘텀**(국내상장 ETF, 월말 1회) + **위성(20~30%) 변동성 돌파**(거래세 면제 ETF, 일단위, 익일시가 청산) + 버퍼 10%. 주문 6관문 파이프라인·상태 영속·계좌=진실의 원천·검증 게이트(백테스트→모의 4주 무인→실전 소액→증액).

**질문**: 이 기준으로 시스템을 더 견고하게 만드는 방법은 무엇이며, 리팩토링/전면 재설계가 필요하다면 타당한가?

## 1. 감사 방법

- 룰북 8·9장 + 명세 §1~5에서 **감사 기준 46건** 추출 → 5영역(engine5 리스크·engine3 백테스트/KIS·engine4/전략층·docs 정본·횡단 ops) 병렬 감사.
- 판정 규약: `present`(구현·실배선) / `partial`(일부 또는 미배선) / `absent`(증거 없음). 모든 판정은 파일:라인 증거 필수.
- **absent/partial로 판정된 high 기준 14건은 전수 반박검증** — 별도 에이전트가 전 저장소(backend/src·prisma·scripts·docs·mobile·훅)를 재탐색해 "다른 이름·다른 위치에 이미 존재"할 가능성을 제거. 결과: 1건 승격(A7 멱등성 → present), 1건 승격(B2 워크포워드 → present), 나머지 12건 판정 유지·근거 강화.

### 2-6. 부수 발견 (감사 중 확인된 잠재 결함)

1. `krx-api.service.ts:62` 주석은 "exponential backoff"이나 실제는 선형(retryCount×2000) — 주석·구현 불일치.
2. **일별 상태 플래그 미적재로 백테스트가 상한가 추격·정지종목 진입을 못 걸러냄** → 수익률 낙관 편향 가능 (B5, → P25).
3. `d0-calculator.ts` KNOWN_HOLIDAYS 2026년 목록 5건뿐 — **하반기 공휴일(광복절·추석·개천절·한글날 등) 누락 시 EventStudy D0 산정 오류** (B10, → P09, 시한성 있음).
4. 모의운용 후보 보강 폴백(DAR-362)이 유동성 게이트를 우회 — 저유동성 종목 혼입 가능 (B6).
5. KIS 유량초과는 HTTP 200 본문 msg_cd=EGW00201로 오는 경우가 많아 현 retryCondition(429/503)에 안 잡힘 (B8, → P08).

## 3. 판정: 전면 재설계 불타당 — 증축(incremental-extension) 채택

두 설계안(증축 vs 스트랭글러식 재설계)을 독립 작성 후 심판 판정. **verdict = incremental-extension.**

### 3-1. 판정 근거

1. **갭의 성격 = 배선/모듈 부재가 지배적, 아키텍처 결함은 국소적.** 다수 갭이 "완성된 순수 룰 + 미배선" 패턴이다: `checkAutoKill`(완성·호출자 0), DAILY_LOSS 룰(단타만 소비), KillSwitchState(영속·복원 완비), OrderRequest 스키마(기적용·M11 게이트로 의도적 휴면). 재작성이 아니라 배선 이슈로 메우는 것이 최소비용·최소위험.
2. **M10 클록 보호.** 클록이 오늘(7/3) 리셋됐고 첫 체결 앵커가 7/4다 — 측정 윈도 초입에 2,450줄 핫스팟(paper-simulation.service.ts)의 체결 의미론을 포트로 이동하는 것은 최악의 타이밍. 재설계안 스스로 "기존 5트랙 30일 동결"을 약속하는데, 그 경우 재설계의 실질 수익은 어차피 졸업(≈8월 초) 후에야 실현된다. 같은 시점에 수렴한다면 블라스트 반경이 작고 이중 경로 유지 비용이 없는 증축이 우월.
3. **자산 재사용.** 증축안은 30일 측정 표본을 온전히 보존하며 신규 2트랙을 병행 대조군으로 추가해 같은 질문("무엇이 실계좌 면허를 받는가")에 답한다. 재설계안은 5트랙 측정 표본의 전략 레벨 결론을 퇴역 심사로 폐기 위험에 노출.
4. **Paperclip 실행 적합성.** S/M 위주 27건이 XL 1건 포함 10건보다 플릿의 이슈 단위 실행에 명백히 적합. 이 저장소의 검증된 성공 패턴(분봉단타 5번째 트랙 additive 추가·styleTag 네임스페이스 병행)은 전부 증축형.
5. **재설계안의 정당한 통찰은 흡수.** "트랙별 인라인 배선이 드리프트를 유도"(forward 2개 서비스 킬스위치 참조 0건으로 실증)는 사실 — 처방은 XL 게이트웨이가 아니라 **P18(공용 RiskGuard 게이트 추출) + P22(주문 6관문 섀도 원장 + 포트 인터페이스)**로 스트랭글러의 씨앗을 선취한다.

**기각 사항**: Python 트레이딩 스택 분리(외부 문서의 Python 전제는 구현 세부이지 요건 아님 — 3,200+ 테스트·KIS 연동·측정층 폐기 대비 얻는 엣지 0), engine1~4 재작성, 그린필드. **"M11은 어차피 실행 포트가 전제"** 논거는 참이나 시기상조 — M11은 엣지 미증명으로 보류 확정 상태이고, 엣지 증명 전의 게이트웨이 구축은 무검증 전략에 실행 인프라를 선투자하는 것. 재검증 2회차 결과 시점에 P22의 포트 인터페이스 위에서 착수해도 늦지 않다.

## 5. 리스크 (설계·심판 계상)

1. **P18 배선 실수 = M10 클록 재리셋 사유.** "게이트 호출 1줄" 원칙 + 기존 spec 회귀(jest 3254+) + 배포 전후 사이클 산출 diff 검증을 이슈 DoD에 명시.
2. **ETF 데이터 기반(P10)이 신규 트랙의 단일 실패점** — KRX `/etp/etf_bydd_trd` 인증·쿼터·포맷 미검증, TIGER 미국S&P500 상장(2020-08) 이전 구간 부재(대체 지수 보완 여부 이슈 내 결정).
3. **월말 크론(P13)은 P09 월말 거래일 판정에 의존** — 오발화/미발화가 코어 트랙 측정을 통째로 왜곡. 데이터 주도(일봉 실재일) 폴백 필수.
4. **위성 전략 엣지 미검증** — P16 게이트 통과 전 forward 활성 금지(위성 25% 자본을 무검증 전략에 노출 금지).
5. **P01 Prisma 마이그레이션이 알림 계열 전체의 병목** — 휴먼 승인(ask) + 스키마 직렬 처리 규약 준수.
6. **Paperclip 병렬 구현 시 공유 접점**(paper-simulation.service.ts·forward-tracks.scheduler.ts·schema.prisma) — 이슈 발행 시 파일 소유 경계·순서 명시 필수.
7. **플릿의 "구현 완료=발효" 오해 방지** — 각 이슈 본문에 SHADOW 기본값을 수용 기준으로 명기.
8. **장중 폴링 증가(P15)가 KIS 쿼터 잠식** — P08 선행 + 호출량 재배분 검증 없이는 기존 측정 트랙의 데이터 신선도까지 오염 가능.
9. **월단위 전략의 통계 검증력 한계** — 연 12회 관측뿐이라 자체 백테스트 검증력이 낮고, 결국 문헌상 엣지(듀얼모멘텀)에 기대는 결정임을 정직하게 인지.
10. **제품 정체성** — 2단 코어는 공시와 무관한 가격 기반. "코어=안정 기반, 공시 트랙=위성 알파" 재서사는 제품 오너(사용자) 승인 사안.
