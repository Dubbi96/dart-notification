# 정책 기획 (plan-policy) — 역할 문서

> 작성일: 2026-06-02 · 상태: 기준선 확정

---

## 1. 역할 정의 & 책임 범위

### 이 파트가 소유하는 것

정책 기획 파트는 서비스의 **컴플라이언스 전체**를 소유한다. 구체적으로:

- **약관·개인정보처리방침**: 기존 `legal/terms`, `legal/privacy` 화면의 내용 정의 및 버전 관리. 각 기능 확장(시세, 매매, 자동매매) 시 갱신 트리거 발동.
- **비투자자문 고지**: 자본시장법상 유사투자자문업 경계 유지. "이 앱은 투자 판단의 참고 자료를 제공하며 투자자문업에 해당하지 않는다"는 법적 고지 문구 작성.
- **AI 한계·정보 정확성 면책**: AI 분석 결과의 오류 가능성, 공시 파싱 오류 가능성, 지연 데이터 위험에 대한 면책 고지.
- **데이터 출처·라이선스 정책**: DART OpenAPI 이용 약관, KRX 데이터마켓플레이스 라이선스, 증권사 OpenAPI(KIS) 이용 조건을 서비스에 반영하는 방식 정의.
- **모의투자 고지**: 가상 자산·가상 주문 명시, 실거래와의 구분 강제.
- **실매매 약관·리스크 동의**: 반자동매매 진입 전 사용자 동의 절차 및 고지 내용.
- **자동매매 정책**: 허용 이벤트·한도·Kill Switch·자동중단 조건·책임 한계를 서비스 정책 문서로 확정.
- **증권사 연동 약관·민감정보 처리**: KIS 계좌 정보 입력·보관·삭제에 관한 정책.

### 다른 파트와의 경계

| 경계 대상 | 이 파트 | 상대 파트 |
|-----------|---------|-----------|
| 고지 문구 위치·노출 시점 | 정책 문구 내용(what)과 고지 필수 여부(when) 정의 | 화면 기획이 와이어프레임상 노출 위치(where) 구현, FE가 코드로 렌더링 |
| Risk Engine 한도 수치 결정 | 수치 결정 권한 없음. 정책 문서에서는 "AI가 결정 불가"임을 명시하고 공개 고지 방식만 정의 | BE가 `RISK_HARD_RULES` 상수로 구현, DQ가 백테스트 기반 수치 검증 |
| 약관 UI 컴포넌트 | 화면 설계 없음 | 화면 기획(plan-screen)이 모달·동의 체크박스 와이어프레임 작성 |
| 온보딩·주문 흐름 시나리오 | 정책 단계에서 동의가 필요한 시점만 정의 | 시나리오 기획(plan-scenario)이 사용자 여정·분기 흐름 정의 |

## 2. 마일스톤별 업무 (M0~M12)

### M0 — 기준선 & 수집 안정화 | **R (주담당)**

**이 역할이 할 작업:**

- [ ] **서비스 범위 선언 문서 초안 작성**: "이 앱이 하는 것 / 하지 않는 것"을 공개 고지 가능한 수준으로 문서화. 분석 리포트 + 모의투자 중심, 자동매매 금지 선언.
- [ ] **비투자자문 고지 문구 초안 작성**:
  - 목적: 자본시장법 제17조·유사투자자문업 규제 준수.
  - 필수 고지 문구 방향: "본 서비스는 투자자문업이 아닙니다. 제공되는 분석 리포트·공시 요약·Buy Score는 투자 판단의 참고 자료로만 활용하시고, 최종 투자 결정과 그에 따른 손익은 투자자 본인에게 있습니다."
  - 노출 위치: 온보딩 최초 1회 팝업 동의 + 앱 설정 > 법적 고지 상시 접근.
- [ ] **초기 약관(Terms of Service) v0.1 초안**:
  - 서비스 정의, 대상 기능 범위(공시 알림·분석 리포트), 책임 제한, 서비스 변경·종료 정책, 분쟁 해결.
- [ ] **개인정보처리방침 v0.1 검토·갱신**:
  - 기존 화면(`legal/terms`, `legal/privacy`)의 내용이 M0 시점 기능(카카오 로그인, 디바이스 토큰, 관심기업, 알림 설정)을 정확히 반영하는지 확인.
  - 수집 항목: 이메일(OAuth), 디바이스 토큰, 관심기업 목록, 알림 이력.
  - 수집·이용 목적: 공시 알림 서비스 제공.
  - 보유·파기 기간 명시.
- [ ] **AI 금지영역 내부 정책 문서 확정**: "최종 주문 승인·손익 하드룰·포트폴리오 한도·주문 수량·리스크 우회는 AI가 결정하지 않는다"를 서비스 내부 정책으로 문서화. 각 Phase 진입 시 이 문서를 기준으로 컴플라이언스 확인.

**이 단계에서 받아야 할 입력:**
- 비전 문서(§4 AI 금지영역, §3 3대 원칙) — 이미 존재
- 개발 예정 기능 목록(docs/archive/feature-status.md — 2026-06-02 인수 시점 스냅샷, 아카이브됨) — 이미 존재
- 초기 공시 5종, Persona 4종 범위 확정(phase-00-baseline-scope.md) — 이미 존재

### M1 — 공시 원문 파싱 | **해당 없음 (다른 파트 산출물 대기)**

BE/DQ가 주담당. 이 역할은 작업 없음.

**확인할 점:** 원문 파싱 오류·파싱 실패 케이스 발생 시 "파싱 정확도 면책 고지" 범위에 포함될 수 있는지 M2 전에 사전 확인.

---

### M2 — 이벤트·수치 추출 | **해당 없음 (다른 파트 산출물 대기)**

BE/DQ가 주담당.

**확인할 점:** Rule 기반 수치 추출 정확도가 85% 이상이 되지 않는 경우, AI 분석 결과와 결합한 고지 문구에서 "데이터 정확성의 한계" 문구가 필요한지 M3 착수 전 점검.

### M3 — AI Analyst + 비용계측 토대 | **C (협업)**

AI 파트가 주담당. 정책 기획의 협업 작업:

- [ ] **AI 한계·정보 정확성 면책 고지 문구 작성**:
  - 목적: AI 분석 결과(공시 요약, Buy Score, Persona 해석)의 오류 가능성 고지.
  - 필수 고지 문구 방향: "AI 분석은 외부 LLM API를 사용하며, 분석 결과의 정확성을 보장하지 않습니다. 동일 공시에 대해 AI가 상이한 해석을 생성할 수 있으며, 이벤트 분류·긍부정 판단에 오류가 포함될 수 있습니다."
  - 노출 위치: AI 분석 리포트 화면 하단 상시 표시 + 최초 AI 기능 활성화 시 동의.
- [ ] AI 분석 결과 화면에 "이 분석은 투자 권유가 아닙니다" 문구를 표시하는 정책 항목 화면 기획에 전달.
- [ ] 약관(Terms of Service) v0.2 갱신: AI 기능 도입 반영 (AI 분석 서비스 정의, AI 오류 면책, 외부 LLM API 제3자 서비스 이용 고지).

**받아야 할 입력:** AI 파트로부터 4개 AI Task 목록, 출력 결과물의 성격(요약/분류/해석), 오류 처리 방식.

### M4 — 시세·시장 데이터 (KRX) | **C (협업)**

BE/DQ/인프라가 주담당. 정책 기획의 협업 작업:

- [ ] **데이터 출처·라이선스 정책 문서 작성**:
  - DART OpenAPI: 금융감독원 제공 공공 데이터, 이용 조건(비상업적/상업적 허용 여부, 출처 표기 의무) 확인 후 고지 방식 정의.
  - KRX 데이터마켓플레이스: 한국거래소 공기업 제공. 라이선스 조건(재배포 금지, 출처 표기, 유료 이용권 조건) 확인. 앱 내 "데이터 출처: 한국거래소" 표기 의무 여부 결정.
  - 목적: 외부 데이터 저작권·이용 약관 위반 방지.
  - 노출 위치: 앱 설정 > 데이터 출처 안내 화면.
- [ ] 약관 v0.3 갱신: 시세 데이터 제3자 제공 항목 추가, 데이터 지연 가능성 면책 고지. "표시되는 시세는 최대 N분 지연될 수 있으며 체결가의 기준이 되지 않습니다."

**받아야 할 입력:** DQ 파트로부터 KRX 데이터마켓플레이스 계약 조건(상업적 이용 허용 여부, 재배포 정책 요약).

### M6 — 매수 Signal Engine | **C (협업)**

BE/DQ/FE가 주담당. 정책 기획의 협업 작업:

- [ ] **Buy Score 고지 정책 확정**:
  - "Buy Score는 투자 권유 지수가 아닙니다. 점수는 공시 수치·기술지표·과거 통계를 Rule 기반으로 종합한 참고 지표이며, 실제 주가 상승을 예측하지 않습니다." 고지 위치: Signal 카드 내 툴팁 또는 하단 주석.
- [ ] **과거 통계 기반 면책 문구 작성**: "과거 이벤트 반응 통계는 미래 결과를 보장하지 않습니다." 노출 위치: Signal 리포트 및 Event Study 결과 화면.
- [ ] 약관 v0.4 갱신: Buy Score·TradingSignal 기능 정의 추가, 매수 권유 아님 명시.

### M10 — 모의투자 + 비용 거버넌스 ★ | **R (주담당)**

이 파트의 핵심 마일스톤. 모의투자 기능 도입에 따른 고지·정책 전담.

**이 역할이 할 작업:**

- [ ] **모의투자 고지 문구 작성 (핵심)**:
  - 목적: 사용자가 모의투자를 실거래로 오해하지 않도록 법적·UX 차원에서 명확히 구분.
  - 필수 고지 문구: "모의투자는 가상 자산으로 진행하는 시뮬레이션입니다. 모의투자에서 발생하는 수익·손실은 실제 금전 손익이 아니며, 실제 주문이 집행되지 않습니다. 모의투자 성과는 실제 투자 성과와 다를 수 있습니다."
  - 노출 위치: ①모의투자 포트폴리오 생성 시 별도 동의 화면(체크박스 필수), ②모의 포트폴리오 대시보드 헤더 상시 표시("모의투자 — 실거래 아님"), ③모의 주문 체결 알림 Push에 "[모의]" 태그.
- [ ] **모의투자 전용 동의서 v1.0 작성**:
  - 동의 항목: 가상 자산임을 인지함, 실거래 아님을 인지함, 모의 성과가 실성과를 보장하지 않음을 인지함.
  - 동의 방식: 온보딩 모의투자 진입 시 체크박스 3개 + 하단 확인 버튼.
- [ ] **AI 비용 고지 정책 확정**: 모의투자 구간 AI 호출 비용은 서비스 운영 비용으로 처리됨을 내부 정책 확정. 사용자 과금 없음 명시.
- [ ] 약관 v0.5 갱신: 모의투자 서비스 정의, 가상 자산 명시, 모의 성과 면책 조항 추가.
- [ ] **MVP 졸업 게이트 컴플라이언스 체크**: AI 금지영역 침범 0 확인(감사 로그 기준). 이 역할이 체크리스트 항목 작성 후 QA 파트에 전달.

### M11 — 반자동매매 | **R (주담당)**

이 파트의 핵심 마일스톤. 실매매 전 사용자 동의 및 고지 전담.

**이 역할이 할 작업:**

- [ ] **실매매 약관 v1.0 작성**:
  - 서비스 정의: 반자동매매란 "AI 분석·Buy Score를 참고해 시스템이 주문안을 제시하고, 사용자가 직접 승인·거절·관망을 선택하는 방식"임을 정의.
  - 책임 한계: "사용자 승인 후 집행된 주문에 대한 손익은 사용자 본인에게 있습니다. 시스템이 제시한 주문안을 승인한 이후의 결과에 대해 서비스 운영사는 책임을 지지 않습니다."
  - AI 역할 명시: "AI는 분석·추천 단계에만 관여하며, 최종 주문 승인은 사용자 본인의 결정입니다. 주문 수량·가격은 Risk Engine이 Rule 기반으로 산출하며 AI가 결정하지 않습니다."
  - 증권사 API 연동 항목: KIS OpenAPI 계좌 연동 시 계좌 정보 처리, 증권사 API 오류 시 책임 범위.
- [ ] **투자 리스크 고지 v1.0 작성**:
  - 주식 투자 원금 손실 가능성 고지.
  - 공시 정보 지연·오류 가능성 고지.
  - 시스템 장애·증권사 API 오류로 인한 주문 미체결 가능성 고지.

## 5. 역할 특화 표준·체크리스트

### 정책 항목서 작성 표준

정책 기획이 화면·FE·BE에 전달하는 모든 고지 항목서는 아래 형식을 따른다:

```
항목명: [고지 이름]
목적: [왜 이 고지가 필요한가 — 법적/UX/컴플라이언스]
필수 고지 문구 방향: [실제 앱에 표시될 문구의 방향 (최종 카피라이팅은 화면 기획과 협업)]
노출 위치: [온보딩 / 주문 전 동의 / 화면 하단 상시 / 설정 > 법적 고지]
노출 방식: [팝업 1회 동의 / 상시 텍스트 / 체크박스 필수 / 툴팁]
갱신 트리거: [이 항목이 갱신되어야 하는 기능 변경 조건]
```

### 약관·개인정보처리방침 갱신 게이트

약관 또는 개인정보처리방침을 갱신할 때는 반드시:

- [ ] 갱신 버전(vX.Y)과 시행일(YYYY-MM-DD) 명시
- [ ] 기존 버전 대비 변경 사항 요약(1~3줄 변경 이력)
- [ ] 앱 내 "약관 변경 안내" 팝업 고지 여부 결정(중요 변경 시 필수)
- [ ] 동의 방식 변경(기존 묵시적 동의 → 명시적 동의 필요 여부) 확인

### 동의서 게이트 원칙

동의서(모의투자·실매매·자동매매)는 아래 조건을 모두 충족해야 화면 기획에 전달된다:

- [ ] 동의 항목이 구체적 사실 기반("위험이 있다" X → "주식 투자는 원금 전액 손실이 가능하다" O)
- [ ] 체크박스 항목이 개별 항목별로 분리 (일괄 동의 단독 사용 금지)
- [ ] 동의 없이 다음 단계 진입 불가 구조를 화면 기획에 명시 요청

### AI 금지영역 컴플라이언스 체크리스트 (M10 이후 매 마일스톤)

| 항목 | 확인 방법 | 담당 |
|------|---------|------|
| AI가 최종 주문 승인을 결정하는 코드 없음 | TradingAuditLog의 actor 필드: AI 없음 확인 | QA + 정책 기획(고지 정합성) |
| AI가 손절·익절 하드룰 수치를 변경하는 코드 없음 | `RISK_HARD_RULES` 상수 파일 수정 이력 감사 | QA + 정책 기획(정책 문서 정합성) |
| AI가 포트폴리오 한도를 결정하는 코드 없음 | Risk Engine 코드 리뷰 | QA |
| AI가 주문 수량을 직접 결정하는 코드 없음 | `calcOrderShares()` 함수 코드 리뷰 | QA |
| 약관·동의서의 AI 역할 설명이 코드 실제 동작과 일치함 | 정책 문서 ↔ 코드 대조 | 정책 기획 |

### 비투자자문 경계 판단 기준

서비스 기능이 아래 기준을 넘으면 반드시 법률 검토가 필요하다. 이 역할이 1차 판단 후 필요 시 외부 법률 검토를 요청한다.

| 허용 범위 | 경계선 | 금지 |
|---------|-------|------|
| 공시 내용 요약·분류 | "~공시가 발생했습니다" | "~를 매수하는 것이 좋겠습니다" |
| 과거 통계 기반 참고 지표 제시 | Buy Score + 면책 표시 | 목표 주가 제시 |
| 포트폴리오 현황 표시 | 잔고·수익률 표시 | 자산 배분 권유 |
| 모의투자 결과 표시 | [모의] 구분 태그 필수 | 모의 성과를 실성과처럼 광고 |
