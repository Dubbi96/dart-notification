# 시나리오(UX) 기획 역할 문서

> 작성일: 2026-06-02 · 역할 코드: 시나리오 · 기준 문서: [비전](../00-vision-and-principles.md) · [실행 로드맵](../01-execution-roadmap.md)

## 1. 역할 정의 & 책임 범위

### 이 파트가 소유하는 것

시나리오(UX) 기획은 **사용자가 앱을 통해 경험하는 모든 여정(Journey)과 분기(Branch)를 텍스트로 설계**한다.
화면 와이어프레임(화면 기획 파트)이나 DB 스키마(BE 파트)가 아니라, 사용자가 특정 트리거를 받은 뒤 어떤 단계를 거쳐 어떤 결과에 도달하는지 — 정상 흐름·분기·예외·빈 상태·알림 카피까지 — 를 명세한다.

**소유 산출물:**
- 온보딩 여정 시나리오 (Persona 선택, 관심 종목 등록 유도)
- 공시 분석 알림 수신 후 사용자 행동 시나리오
- 공시 발생 → 푸시 → 매수 후보 확인 여정
- 신호 → Thesis 확인 흐름
- 매도 알림 → 액션(HOLD/WATCH/REDUCE/EXIT) 선택 시나리오
- 모의투자 일상 운용 시나리오 (장전/장중/장후)
- 주문 승인 시나리오 (승인/거절/관망, Risk 거부 케이스)
- 자동매매 가동/중단·Kill Switch·연속손실 중단 시나리오
- 각 시나리오의 알림 카피 톤(tone) 정의

**3대 원칙을 시나리오 관점에서 지키는 방법:**
1. AI는 모든 공시에 쓰지 않는다 → AI 분석이 없는 공시는 "요약 분석 준비 중" 빈 상태 시나리오로 처리하고, 사용자가 원문을 직접 볼 수 있는 경로를 항상 제공한다.
2. 매수보다 매도·포트폴리오 추적을 먼저 안전하게 설계한다 → 매도 알림 시나리오(M8)는 매수 시나리오(M6)보다 더 상세한 분기와 빈 상태를 정의한다. "매도 알림은 놓치면 손해"이므로, 매수보다 더 강한 인터럽트(푸시·배너) 설계를 요구한다.
3. 자동매매는 마지막 단계다 → M0~M10 모든 매매 관련 화면에 "투자 자문 아님·참고용" 면책 맥락을 시나리오 단계에 포함한다. M11(반자동)부터는 Risk 거부 케이스 시나리오를 별도로 작성한다.

### 다른 파트와의 경계

| 경계 파트 | 이 파트가 하는 것 | 저 파트가 하는 것 |
|-----------|------------------|------------------|
| 화면(UI) 기획 | 사용자 행동 단계·분기·알림 카피 텍스트 | 와이어프레임·컴포넌트 레이아웃·정보 구조 |
| FE (앱 개발) | 시나리오 명세·화면 전환 조건 | React Native 컴포넌트·훅·네비게이션 구현 |
| 정책 기획 | 투자 자문 아님 문구의 등장 시점·맥락 | 투자 자문 아님 법적 문구 내용·약관 |
| BE (백엔드) | API가 어떤 상태를 반환해야 시나리오가 작동하는지 요구 명세 | API 실제 구현 |
| QA | 시나리오 분기가 테스트 케이스로 전환될 수 있도록 분기 명확화 | 실제 테스트 실행 |

## 2. 마일스톤별 업무 (M0~M12)

### M0 — 기준선 & 수집 안정화 | R (주담당)

**이 단계에서 할 일:**
- [ ] 온보딩 시나리오 v1 작성
  - 트리거: 앱 첫 실행 / 카카오 로그인 완료 직후
  - 단계 1: "관심 종목을 1개 이상 등록해야 공시 알림을 받을 수 있습니다" 유도 화면 진입
  - 단계 2: 인기 기업 목록(cold start fallback) 표시 → 탭하면 즉시 등록
  - 단계 3: 검색 모달 진입 → 자동완성 → 등록
  - 분기 A (성공): 1개 이상 등록 완료 → "알림 설정으로 이동" 또는 홈 피드 진입
  - 분기 B (건너뜀): 사용자가 건너뜀 → 홈 피드 진입 후 빈 상태 배너 상시 표시
  - 빈 상태: 관심 종목 0개일 때 홈 피드 — "아직 관심 종목이 없어요. 추가하면 맞춤 공시 알림을 받을 수 있어요." + [종목 추가] 버튼
- [ ] Persona 선택 시나리오 v1 작성 (M3 AI 도입 전 준비)
  - 트리거: 온보딩 완료 직후 또는 설정 탭 내 "투자 성향" 메뉴
  - Persona 4종 설명 카드: 가치투자형 / 성장주형 / 모멘텀형 / 이벤트드리븐형
  - 각 카드: 성향 한 줄 설명 + 선호 공시 예시 + "이런 분께 추천" 문구
  - 선택 후: "선택하신 성향에 맞는 공시 분석이 제공됩니다. 언제든 변경할 수 있습니다."
  - 미선택 시: 기본값 이벤트드리븐형 자동 적용, 설정 탭에 "성향 미설정" 배지 표시
  - 면책 문구: "Persona는 투자 자문이 아니며 참고용 분류입니다."
- [ ] 공시 목록 빈 상태 시나리오: 관심 종목 등록 후 당일 공시가 없을 때 — "오늘은 관심 종목의 공시가 없어요. 새 공시가 오면 알려드릴게요."
- [ ] 알림 권한 거부 시나리오: 푸시 권한 미허가 → "알림을 허용해야 새 공시를 빠르게 받을 수 있어요." + [설정에서 허용하기] 버튼

**이 마일스톤에서 확인해야 할 기존 자산:**
- 현재 온보딩 화면이 `app/(auth)/onboarding.tsx` 수준에서 어디까지 구현됐는지 FE 파트에 확인
- 카카오 로그인 완료 후 리디렉션 경로가 온보딩 시나리오 진입점과 일치하는지 BE 파트에 확인

### M1 — 공시 원문 파싱 | 해당 없음 (·)

BE/DQ/QA/인프라 파트의 파싱 파이프라인 구현 단계. 시나리오 파트는 직접 작업이 없다.

**이 단계에서 받아야 할 입력/확인할 점:**
- 파싱 실패(`parseStatus = FAILED`) 공시가 앱에 어떻게 노출되는지 FE에 확인 — "원문을 불러오지 못했습니다. DART에서 직접 확인하세요." 빈 상태 문구를 M3 전에 미리 정의해둘 것
- 정정공시(`isAmendment = true`) 공시가 목록에서 구분 표시될 때 사용자에게 보여줄 레이블 톤 검토 — "정정 공시"라는 용어가 일반 사용자에게 자연스러운지 확인

---

### M2 — 이벤트·수치 추출 | 해당 없음 (·)

Rule/Parser 기반 수치 추출 단계. 시나리오 파트는 직접 작업이 없다.

**이 단계에서 받아야 할 입력/확인할 점:**
- 이벤트 enum 5종(`SUPPLY_CONTRACT`, `SHARE_BUYBACK`, `SHARE_CANCELLATION`, `DIVIDEND`, `PAID_IN_CAPITAL`, `CB_BW`)이 앱 화면에서 사용자에게 보여줄 때 어떤 한국어 레이블로 표시할지 결정 — M3 공시 분석 알림 수신 시나리오 작성 전 레이블 목록 확정 필요
- 계약 취소(`isCancellation = true`) 이벤트 처리 시 사용자에게 강조할 문구 톤 검토 요청 사항을 M3 담당에게 전달

### M3 — AI Analyst + 비용계측 토대 | C (협업)

**이 단계에서 할 일:**
- [ ] 공시 분석 알림 수신 시나리오 v1 작성
  - 트리거: 관심 종목에 5종 이벤트 공시 발생 → AI 분석 완료 → 푸시 발송
  - 알림 카피 (AI 분석 있는 경우):
    - 제목: `[공시 알림] {기업명} — {이벤트 레이블}`
    - 본문: `{핵심 포인트 1줄}. Tap to see analysis.`
    - 예시: `[공시 알림] 삼성전자 — 대규모 공급계약` / `매출 대비 24% 규모의 신규 계약. 분석 보기 >`
  - 알림 카피 (AI 분석 없는 경우 / L0 게이트 미통과):
    - 제목: `[공시 알림] {기업명} — {공시 제목}`
    - 본문: `새 공시가 도착했어요. 원문을 확인하세요.`
  - 딥링크 착지점: 공시 상세 화면 → AI 분석 탭(있을 경우) or 원문 탭
  - 빈 상태 (AI 분석 준비 중): "AI 분석을 준비하고 있어요. 잠시 후 다시 확인해 주세요." + [원문 보기] 버튼
  - 면책 맥락: 공시 분석 화면 하단에 고정 표시 — "이 분석은 투자 자문이 아니며 참고 목적으로만 제공됩니다."
- [ ] Persona 해석 탭 시나리오:
  - 공시 상세 → 내 Persona 해석 탭 진입
  - 표시: Persona 이름 + "이 Persona의 관점: {view}" + AI 해석 근거 1~2줄
  - 분기: view = POSITIVE → 초록 배지, WATCH → 노랑 배지, NEGATIVE → 빨강 배지
  - 미설정 시: "성향을 설정하면 맞춤 해석을 받을 수 있어요." + [성향 설정] 링크

### M4 — 시세 데이터 | 해당 없음 (·)

KRX 데이터 파이프라인 구축 단계. 시나리오 파트는 직접 작업이 없다.

**이 단계에서 받아야 할 입력/확인할 점:**
- 종목 상태(거래정지·관리종목·투자주의) 표시가 시나리오에서 중요해지는 M6 전에 레이블 톤을 미리 결정: "거래 정지 종목입니다" vs "현재 거래가 중단된 종목입니다" — 어조 확정 필요

---

### M5 — Event Study | 해당 없음 (·)

통계 분석 단계. 시나리오 파트는 직접 작업이 없다.

**이 단계에서 받아야 할 입력/확인할 점:**
- D+1/D+5 평균 반응 통계를 사용자에게 표시할 때 "과거 유사 공시 반응" 문구와 면책 표현 방식 검토 — M6 시나리오에서 "과거 통계 기반 근거"가 등장하므로 미리 정책 파트와 문구 협의

### M6 — 매수 Signal Engine | R (주담당)

**이 단계에서 할 일:**
- [ ] 공시 발생 → 푸시 → 매수 후보 확인 여정 시나리오 작성
  - **트리거A (강한 매수후보, buyScore ≥ 80):**
    - 푸시 알림 수신
    - 알림 카피: `[매수 후보] {기업명} — Score {buyScore}`  / `{핵심 매수 근거 1줄}. 진입 조건 확인 >`
    - 탭 → 신호 상세 화면 착지
  - **트리거B (매수후보, 60~79):**
    - 알림 카피: `[관심 종목 신호] {기업명} — Score {buyScore}` / `{매수 후보 이유 1줄}`
  - **신호 상세 화면 여정:**
    - 단계 1: Buy Score 시각화 바 (0~100) + 등급 레이블 표시
    - 단계 2: 근거 목록 (공시 이벤트 / 핵심 수치 / Persona 적합도 / 차트 / 거래량)
    - 단계 3: 리스크 요인 목록 (항상 표시, 생략 불가)
    - 단계 4: 진입 조건 체크리스트 — 충족(초록 체크) / 미충족(회색)
    - 단계 5: "참고용 분석입니다" 면책 배너
  - **분기 A (entryReady = true):** 진입 조건 모두 충족 → "지금 진입 가능한 조건이 갖춰졌습니다. 직접 판단 후 투자하세요." (자동 매수 안내 금지)
  - **분기 B (entryReady = false):** 미충족 조건 강조 → "아직 진입 조건 {N}개가 충족되지 않았습니다."
  - **분기 C (BLOCKED):** 거래정지·관리종목 → "현재 이 종목은 매매가 불가합니다. ({차단 사유})"
  - **분기 D (AVOID):** 낮은 점수 → 이 등급에서는 푸시 미발송, 목록에서만 확인 가능
  - **빈 상태:** 신호 목록 비어있을 때 — "오늘 매수 후보 신호가 아직 없어요. 관심 종목에 주요 공시가 발생하면 알려드릴게요."
  - **면책 맥락:** 모든 신호 화면 하단 고정 — "이 신호는 투자 자문이 아닙니다. 최종 매수 결정은 본인의 판단에 따라 이루어집니다."
- [ ] 과거 유사 공시 반응 섹션 시나리오 (Event Study 데이터 연동):
  - "과거 유사 공시 {N}건의 D+5 평균 수익률: {X}%" 표시
  - 하단 면책: "과거 통계가 미래 수익을 보장하지 않습니다."
  - 표본 부족 시 빈 상태: "유사 공시 데이터가 충분하지 않아 통계를 제공하지 않습니다."

### M7 — Position Thesis | C (협업)

**이 단계에서 할 일:**
- [ ] 신호 → Thesis 확인 흐름 시나리오 작성
  - 트리거: 신호 상세 화면에서 [Thesis 저장] 또는 [보유로 등록] 탭
  - 단계 1: Thesis 내용 미리보기 — "매수 논리", "훼손 조건", "목표 보유 기간", "손절/익절 기준"
  - 단계 2: AI가 생성한 `initialThesis[]` 텍스트 목록 표시
  - 단계 3: `invalidConditions[]` — "이런 상황이 오면 매도를 검토하세요" 목록
  - 단계 4: 하드룰 표시 (손절 -7%, 익절 +12% 등) — **수치는 읽기 전용, AI/사용자 직접 수정 불가 문구 명시**
  - 단계 5: [확인 후 저장] 버튼
  - **분기 A (저장 성공):** "포지션 Thesis가 저장되었습니다. 종목 모니터링이 시작됩니다."
  - **분기 B (Thesis 자동 생성 실패):** "AI 분석 실패로 Thesis를 자동 생성하지 못했습니다. 기본 손절(-7%)/보유기간(20영업일) 룰이 적용됩니다." + [직접 입력] 옵션
  - **분기 C (신호 만료 후 접근):** "이 신호는 유효 기간이 지났습니다. 현재 시장 상황을 다시 확인하세요."
  - 면책: "Thesis는 참고 목적이며 손절 기준은 투자 자문이 아닙니다."

### M8 — Portfolio & Exit Engine | R (주담당)

**이 단계에서 할 일:**
- [ ] 매도 알림 → 액션 시나리오 전체 작성 (Exit Score 기반)

  **시나리오 1: HOLD (0~29점)**

  - 알림 없음 (HOLD는 무소음 처리)

  - 액션 버튼: [확인했음] (알림 읽음 처리)

  **시나리오 3: REDUCE (50~69점)**
  - 트리거: 점검 완료 → REDUCE 신호 생성
  - 알림 카피: `[일부 매도 권고] {기업명} — Exit Score {score}` / `{주요 트리거 1줄}. 25~50% 축소를 검토하세요.`
  - 화면 여정:
    - 단계 1: Exit Score 게이지 + "일부 축소" 등급 강조
    - 단계 2: 트리거 분류 목록 (손실/논리훼손/차트훼손/공시악화/과다비중/시간초과 중 해당 항목)
    - 단계 3: AI 논리훼손 설명(있는 경우) — "AI 해석: {aiExplanation}"
    - 단계 4: 현재 포지션 수익률 + 진입가 표시
    - 단계 5: 면책 배너
  - 액션 버튼 3개: [동의·축소 검토] / [보류·계속 관찰] / [무시]

    - "보류": userAction = OVERRIDDEN_HOLD, 무시 횟수 카운트
    - "무시": 무시 횟수 카운트, 3회 이상 시 다음 점검에서 배너 강화

  **시나리오 4: EXIT (70~89점)**
  - 트리거: 점검 완료 → EXIT 신호 생성
  - 알림 카피: `[매도 권고] {기업명} — Exit Score {score}` / `{주요 트리거}. 전량 매도를 검토하세요.`
  - 알림 강도: 일반 알림 (소리 + 진동)
  - 화면 여정: REDUCE와 동일하되 등급 강조 색상 빨강
  - 액션 버튼: [전량 매도 검토] / [유지·재평가]
  - 면책: "매도 권고는 투자 자문이 아닙니다. 최종 결정은 본인이 합니다."

  **시나리오 5: EXIT + BLOCK_REBUY (90점 이상, 즉시 리스크)**
  - 트리거: 즉시 리스크 매도 신호
  - 알림 카피: `[긴급 주의] {기업명} — 즉시 점검 필요` / `리스크 지표가 임계치를 초과했습니다. 지금 확인하세요.`
  - 알림 강도: 반복 알림 (최대 2회)
  - 화면 여정: 모달 인터럽트로 즉시 표시, 확인 전 다른 화면 이동 시 배너 고정
  - 재매수 금지 안내: "이 종목은 당분간 재매수 신호가 생성되지 않습니다."

- [ ] 장전/장중/장후 점검 사이클 시나리오:

  **시나리오 B: 자동매매 실행 알림**
  - 자동 매수 체결: `[자동 매수] {기업명} {수량}주 @ {가격}원` / `{이벤트명} 신호 기반. 포트폴리오에 반영됐습니다.`
  - 자동 매도 체결: `[자동 매도] {기업명} {수량}주 @ {가격}원` / `Exit 신호 기반 자동 청산.`
  - Risk Engine Veto 알림: `[자동매매 차단] {기업명}` / `리스크 규칙 {차단 사유}. 자동 매수가 차단됐습니다.`

  **시나리오 C: Kill Switch 작동**
  - 트리거 A (사용자 수동): 홈 화면 Kill Switch 버튼 탭
    - 확인 모달: "자동매매를 즉시 중단하시겠습니까? 진행 중인 주문은 취소됩니다."
    - [중단] / [취소]
    - 중단 성공: 전체 화면 상단 빨간 배너 — "자동매매 정지 중. 재개하려면 설정에서 다시 활성화하세요."
  - 트리거 B (시스템 자동 — 연속 손실):
    - 푸시: `[자동매매 정지] 연속 손실 {N}회 감지` / `리스크 관리 시스템이 자동매매를 일시 중단했습니다.`
    - 화면: Kill Switch 배너 표시 + 재개 조건 안내
    - 재개 조건 표시: "24시간 후 또는 설정에서 수동으로 재개할 수 있습니다."
  - 트리거 C (시스템 자동 — 일일 손실 한도):
    - 푸시: `[자동매매 정지] 오늘 손실 한도 도달` / `총 자산 2% 손실로 오늘 신규 매수가 중단됩니다.`
    - 재개 조건: "다음 거래일 자동 재개됩니다."
  - 트리거 D (시스템 자동 — API 오류):
    - 푸시: `[자동매매 정지] 증권사 API 오류` / `연결 문제로 자동매매가 중단됐습니다. 확인 후 재개하세요.`
  - Kill Switch 활성 중 신규 공시 발생 시:
    - 앱 내 알림만: "자동매매 정지 중 — {기업명} 신호 발생 (자동 실행 안 됨)"

  **시나리오 D: 연속 손실 중단 상세**
  - 연속 손실 N회 중 각 단계별 경고:
    - 1회: 무음 (기록만)
    - 2회: 앱 내 배너 — "{기업명} 손실 2회 연속. {N}회 더 손실 시 자동매매가 중단됩니다."
    - 3회(중단 기준 도달): Kill Switch 자동 활성 + 즉시 푸시
  - 재개 화면: 연속 손실 내역 요약 + "전략을 재검토하시겠습니까?" + [전략 설정 보기] / [수동 재개]

  **시나리오 E: 롤아웃 레벨 업그레이드 안내**
  - 조건 충족 시 앱 내 알림: "레벨 1 운용 4주 완료. 레벨 2(자산 2%) 승급 조건을 충족했습니다."
  - 승급 요청은 앱 내에서 불가 (관리자 수동 승인) → "고객센터를 통해 승급을 요청하세요."

## 5. 역할 특화 표준·체크리스트

### 시나리오 문서 작성 표준

각 시나리오는 반드시 아래 6항목을 포함한다:

1. **트리거**: 시나리오를 시작하는 이벤트 (푸시 수신 / 화면 접속 / 시스템 이벤트)
2. **단계 (Steps)**: 사용자가 거치는 화면·액션의 순서
3. **분기 (Branches)**: 성공/실패/예외 분기 각각의 처리
4. **빈 상태 (Empty State)**: 데이터가 없거나 서비스 불가 상황의 문구
5. **알림 카피 (Push/In-app)**: 제목, 본문, 딥링크 타입
6. **면책 맥락**: "투자 자문 아님·참고용" 문구가 어느 단계에서 어떤 형태로 표시되는지

### 알림 카피 톤 기준

| 상황 | 톤 | 예시 |
|------|----|------|
| 일반 공시 알림 | 중립·정보 | "새 공시가 도착했어요." |
| 매수 후보 신호 | 적극적·중립 | "매수 후보 신호 발생. 확인하세요." |
| WATCH/주의 신호 | 조심·주의 | "주의 신호 감지. 내일 장 전 확인하세요." |
| REDUCE/EXIT 신호 | 명확·권고 | "매도 권고. 직접 판단 후 결정하세요." |
| 긴급 리스크 (90+) | 긴급·명확 | "긴급 주의. 지금 확인하세요." |
| Risk 거부 | 설명적·중립 | "리스크 규칙 차단. {사유}." |
| Kill Switch 발동 | 명확·안심 | "자동매매가 중단됐습니다. 확인 후 재개하세요." |
| 모의투자 결과 | 친근·중립 | "오늘 모의투자 결과: +{N}%" |

**금지 톤:**
- "지금 당장 사세요" / "반드시 팔아야 합니다" 등 직접 투자 지시형 문구
- "확실한 수익" / "안전한 투자" 등 확정적 수익 보장 표현
- "AI가 추천합니다" 등 AI를 최종 판단 주체로 표현하는 문구

### AI 금지영역 시나리오 게이트

모든 매매 관련 시나리오에서 아래 항목이 **절대 포함되지 않는지** 작성 완료 후 체크:

- [ ] AI가 "이 종목을 사세요"라고 최종 권고하는 문구 없음
- [ ] 손절·익절 수치가 "AI 추천값"으로 표현되지 않음 (읽기 전용·시스템 고정값 표현 사용)
- [ ] 포트폴리오 비중 결정을 AI가 하는 것처럼 표현되지 않음
- [ ] Risk Engine의 거부가 "AI의 거부"로 표현되지 않음 ("자동 리스크 관리 시스템" 사용)
- [ ] 자동매매 승인 시나리오에서 AI가 버튼을 누르거나 결정을 대신하는 흐름 없음
- [ ] Kill Switch 해제가 AI에 의해 이루어지는 흐름 없음
